# 实战场景 — 低代码平台 & 审批流引擎

> 本文档将 Spring 源码中的核心机制与**低代码平台**、**审批流引擎**两个真实业务场景结合，
> 帮助你理解「为什么要这样设计」以及「在实际项目中如何运用」。

---

## 业务背景

### 低代码平台

用户通过可视化拖拽配置表单、页面和逻辑，平台将配置动态转化为可运行的应用。
核心挑战：**运行时动态注册组件、热加载、插件化扩展**。

### 审批流引擎

支持多级审批、会签、加签、驳回、条件分支等复杂流程。
核心挑战：**流程状态流转、事件驱动、事务一致性、权限拦截**。

### 场景 1：低代码 — 运行时动态注册数据源

用户在低代码平台创建了一个新应用，选择了一个新的数据库连接。平台需要**运行时**动态注册一个新的 DataSource Bean，而不是重启服务。

```java
/**
 * 低代码平台：动态数据源注册器
 * 利用 BeanDefinitionRegistry 在运行时动态注册新的 DataSource Bean
 */
@Component
public class DynamicDataSourceRegistrar implements ApplicationContextAware {

    private ConfigurableApplicationContext applicationContext;

    @Override
    public void setApplicationContext(ApplicationContext ctx) {
        this.applicationContext = (ConfigurableApplicationContext) ctx;
    }

    /**
     * 用户在低代码平台配置了新数据源时调用
     * @param appId  应用ID
     * @param config 用户配置的数据库连接信息
     */
    public void registerDataSource(String appId, DbConnectionConfig config) {
        DefaultListableBeanFactory beanFactory =
            (DefaultListableBeanFactory) applicationContext.getBeanFactory();

        String beanName = "dataSource_" + appId;

        // 如果已存在，先销毁旧的
        if (beanFactory.containsBean(beanName)) {
            beanFactory.destroySingleton(beanName);
            beanFactory.removeBeanDefinition(beanName);
        }

        // 构建 BeanDefinition（等价于 XML 中的 <bean> 标签）
        BeanDefinitionBuilder builder = BeanDefinitionBuilder
            .genericBeanDefinition(HikariDataSource.class)
            .addPropertyValue("jdbcUrl", config.getUrl())
            .addPropertyValue("username", config.getUsername())
            .addPropertyValue("password", config.getPassword())
            .addPropertyValue("maximumPoolSize", config.getMaxPoolSize())
            .setDestroyMethodName("close");

        // 运行时注册到容器
        beanFactory.registerBeanDefinition(beanName, builder.getBeanDefinition());

        log.info("动态注册数据源: {} -> {}", beanName, config.getUrl());
    }

    /**
     * 获取指定应用的数据源
     */
    public DataSource getDataSource(String appId) {
        return applicationContext.getBean("dataSource_" + appId, DataSource.class);
    }
}
```

**Spring 源码关联**：
- `DefaultListableBeanFactory.registerBeanDefinition()` — Bean 定义注册
- `AbstractAutowireCapableBeanFactory.createBean()` — 首次 getBean 时触发实例化
- `DisposableBeanAdapter.destroy()` — 销毁旧数据源时调用 `close()`

### 场景 2：审批流 — 动态注册审批处理器

不同企业有不同的审批策略（如：金额>10万需要总监审批），这些策略在管理后台配置后需要动态生效。

```java
/**
 * 审批流引擎：动态注册审批节点处理器
 * 管理员在后台配置了新的审批规则后，动态注册对应的处理器 Bean
 */
@Component
public class ApprovalHandlerRegistrar {

    @Autowired
    private DefaultListableBeanFactory beanFactory;

    /**
     * 根据审批节点配置，动态注册处理器
     * 利用 Spring 的 BeanDefinition 动态注册能力
     */
    public void registerHandler(ApprovalNodeConfig nodeConfig) {
        String beanName = "approvalHandler_" + nodeConfig.getNodeId();

        // 根据节点类型选择不同的处理器类
        Class<?> handlerClass = switch (nodeConfig.getNodeType()) {
            case SINGLE_APPROVE -> SingleApprovalHandler.class;    // 单人审批
            case MULTI_APPROVE  -> CountersignApprovalHandler.class; // 会签
            case AUTO_APPROVE   -> AutoApprovalHandler.class;       // 自动审批（条件判断）
            case NOTIFY         -> NotifyHandler.class;             // 抄送通知
            case CUSTOM_CODE    -> ScriptApprovalHandler.class;     // 自定义脚本（低代码）
            default -> throw new IllegalArgumentException("未知节点类型: " + nodeConfig.getNodeType());
        };

        BeanDefinitionBuilder builder = BeanDefinitionBuilder
            .genericBeanDefinition(handlerClass)
            .setScope(BeanDefinition.SCOPE_PROTOTYPE)  // 多实例，每次审批创建新的
            .addPropertyValue("nodeConfig", nodeConfig);

        beanFactory.registerBeanDefinition(beanName, builder.getBeanDefinition());
    }

    /**
     * 获取审批处理器（Prototype 作用域，每次返回新实例）
     */
    public ApprovalHandler getHandler(String nodeId) {
        return beanFactory.getBean("approvalHandler_" + nodeId, ApprovalHandler.class);
    }
}
```

### 场景 4：审批流 — Bean 初始化时加载流程定义

```java
/**
 * 审批流引擎：流程定义管理器
 * 利用 InitializingBean + SmartLifecycle 在容器启动时加载所有流程定义，
 * 并在容器关闭时优雅释放资源
 */
@Component
public class ProcessDefinitionManager implements InitializingBean, SmartLifecycle, ApplicationContextAware {

    private final Map<String, ProcessDefinition> definitions = new ConcurrentHashMap<>();
    private final ProcessDefinitionRepository repository;
    private volatile boolean running = false;
    private ApplicationContext applicationContext;

    @Autowired
    public ProcessDefinitionManager(ProcessDefinitionRepository repository) {
        this.repository = repository;
    }

    @Override
    public void setApplicationContext(ApplicationContext ctx) {
        this.applicationContext = ctx;
    }

    /**
     * InitializingBean 回调：属性注入完成后执行
     * 校验核心依赖是否就绪
     */
    @Override
    public void afterPropertiesSet() {
        Assert.notNull(repository, "ProcessDefinitionRepository 不能为 null");
        log.info("流程定义管理器初始化，开始校验配置...");
    }

    /**
     * SmartLifecycle.start()：容器完全启动后加载流程定义
     * 比 @PostConstruct 更晚执行，此时所有 Bean 都已就绪
     */
    @Override
    public void start() {
        log.info("开始加载流程定义...");
        List<ProcessDefinition> allDefs = repository.findAllEnabled();
        for (ProcessDefinition def : allDefs) {
            // 校验流程定义的合法性
            validateDefinition(def);
            definitions.put(def.getProcessKey(), def);
        }
        this.running = true;
        log.info("流程定义加载完成，共 {} 个活跃流程", definitions.size());

        // 发布自定义事件，通知其他组件流程引擎已就绪
        applicationContext.publishEvent(new ProcessEngineReadyEvent(this, definitions.size()));
    }

    /**
     * SmartLifecycle.stop()：容器关闭时优雅停止
     * 等待正在执行的审批流程完成
     */
    @Override
    public void stop() {
        log.info("流程引擎关闭中，等待进行中的流程...");
        // 设置标志位，拒绝新的审批请求
        this.running = false;
        // 等待进行中的审批任务完成（最多等 30 秒）
        waitForRunningInstances(Duration.ofSeconds(30));
        definitions.clear();
        log.info("流程引擎已关闭");
    }

    @Override
    public boolean isRunning() { return running; }

    @Override
    public int getPhase() { return Integer.MAX_VALUE - 100; } // 晚启动、早关闭

    private void validateDefinition(ProcessDefinition def) {
        if (def.getNodes().isEmpty()) {
            throw new InvalidProcessDefinitionException("流程 [" + def.getProcessKey() + "] 没有定义任何节点");
        }
        // 校验是否有开始节点和结束节点
        boolean hasStart = def.getNodes().stream().anyMatch(n -> n.getType() == NodeType.START);
        boolean hasEnd = def.getNodes().stream().anyMatch(n -> n.getType() == NodeType.END);
        if (!hasStart || !hasEnd) {
            throw new InvalidProcessDefinitionException("流程 [" + def.getProcessKey() + "] 缺少开始或结束节点");
        }
    }
}
```

**Spring 源码关联**：
- `InitializingBean.afterPropertiesSet()` — 在 `AbstractAutowireCapableBeanFactory.initializeBean()` 中调用
- `SmartLifecycle.start()` — 在 `AbstractApplicationContext.finishRefresh()` → `DefaultLifecycleProcessor.onRefresh()` 中调用
- 执行顺序：`@PostConstruct` → `InitializingBean` → `SmartLifecycle.start()`

### 场景 5：低代码 — BeanPostProcessor 实现表单校验器自动注册

```java
/**
 * 低代码平台：自动发现并注册表单字段校验器
 * 利用 BeanPostProcessor，在每个 Bean 初始化后检查是否实现了 FieldValidator 接口
 */
@Component
public class FieldValidatorAutoRegistrar implements BeanPostProcessor {

    private final FieldValidatorRegistry registry;

    @Autowired
    public FieldValidatorAutoRegistrar(FieldValidatorRegistry registry) {
        this.registry = registry;
    }

    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        if (bean instanceof FieldValidator validator) {
            // 读取 @ValidatorFor 注解获取支持的字段类型
            ValidatorFor annotation = AnnotationUtils.findAnnotation(bean.getClass(), ValidatorFor.class);
            if (annotation != null) {
                for (String fieldType : annotation.value()) {
                    registry.register(fieldType, validator);
                    log.info("注册字段校验器: {} -> {}", fieldType, beanName);
                }
            }
        }
        return bean;
    }
}

// 使用示例
@ValidatorFor({"phone", "mobile"})
@Component
public class PhoneFieldValidator implements FieldValidator {
    @Override
    public ValidationResult validate(Object value, FieldConfig config) {
        String phone = String.valueOf(value);
        if (!phone.matches("^1[3-9]\\d{9}$")) {
            return ValidationResult.fail("手机号格式不正确");
        }
        return ValidationResult.ok();
    }
}

@ValidatorFor({"idcard"})
@Component
public class IdCardFieldValidator implements FieldValidator {
    @Override
    public ValidationResult validate(Object value, FieldConfig config) {
        // 身份证号校验（18位 + 校验位）
        return IdCardUtil.isValid(String.valueOf(value))
            ? ValidationResult.ok()
            : ValidationResult.fail("身份证号格式不正确");
    }
}
```

### 场景 7：审批流 — 事件驱动的流程状态通知

```java
/**
 * 审批流引擎：流程事件体系
 * 利用 Spring 事件机制实现审批流程各节点的解耦通知

// ========== 事件定义 ==========

/**
 * 审批事件基类
 */
public abstract class ApprovalEvent extends ApplicationEvent {
    private final String processInstanceId;
    private final String processKey;
    private final Map<String, Object> variables;

    protected ApprovalEvent(Object source, String processInstanceId,

        this.processKey = processKey;
        this.variables = variables;
    }
    // getters...
}

/** 流程发起事件 */
public class ProcessStartedEvent extends ApprovalEvent {

        super(source, instanceId, processKey, variables);
        this.initiatorId = initiatorId;
    }
}

/** 任务待审批事件 */
public class TaskPendingEvent extends ApprovalEvent {
    private final String taskId;
    private final List<String> assigneeIds;  // 审批人列表
    private final String nodeName;           // 节点名称

    // constructor...
}

/** 审批通过事件 */
public class TaskApprovedEvent extends ApprovalEvent {
    private final String taskId;
    private final String approverId;
    private final String comment;
    // constructor...
}

/** 审批驳回事件 */
public class TaskRejectedEvent extends ApprovalEvent {
    private final String taskId;
    private final String rejecterId;
    private final String reason;
    private final String rejectToNodeId;  // 驳回到哪个节点
    // constructor...
}

public class ProcessCompletedEvent extends ApprovalEvent {
    private final ProcessResult result;  // APPROVED / REJECTED / CANCELLED
    // constructor...
}

// ========== 事件发布 ==========

/**
 * 审批流程引擎核心：在状态流转时发布事件
 */
@Service
public class ApprovalEngine {

    @Autowired
    private ApplicationEventPublisher eventPublisher;

    @Autowired
    private ProcessInstanceRepository instanceRepository;

    /**
     * 发起审批
     */
    @Transactional
    public String startProcess(String processKey, String initiatorId, Map<String, Object> formData) {
        // 1. 创建流程实例
        ProcessInstance instance = instanceRepository.create(processKey, initiatorId, formData);

        // 2. 找到第一个审批节点，创建待办任务
        ProcessNode firstNode = instance.getDefinition().getFirstApprovalNode();
        List<String> assignees = resolveAssignees(firstNode, formData);
        taskRepository.createTasks(instance.getId(), firstNode, assignees);

        // 3. 发布流程启动事件
        eventPublisher.publishEvent(new ProcessStartedEvent(
            this, instance.getId(), processKey, initiatorId, formData));

        // 4. 发布任务待审批事件
        eventPublisher.publishEvent(new TaskPendingEvent(
            this, instance.getId(), processKey, firstNode.getName(), assignees));

        return instance.getId();
    }

    /**
     * 审批通过
     */
    @Transactional
    public void approve(String taskId, String approverId, String comment) {
        ApprovalTask task = taskRepository.findById(taskId);
        ProcessInstance instance = instanceRepository.findById(task.getProcessInstanceId());

        // 1. 更新任务状态
        task.approve(approverId, comment);
        taskRepository.save(task);

        // 2. 发布审批通过事件
        eventPublisher.publishEvent(new TaskApprovedEvent(
            this, instance.getId(), instance.getProcessKey(), taskId, approverId, comment));

        // 3. 推进流程到下一节点
        ProcessNode nextNode = instance.moveToNext(task.getNodeId());
        if (nextNode == null) {
            // 流程结束
            instance.complete(ProcessResult.APPROVED);
            instanceRepository.save(instance);
            eventPublisher.publishEvent(new ProcessCompletedEvent(
                this, instance.getId(), instance.getProcessKey(), ProcessResult.APPROVED));
        } else {
            // 创建下一节点的待办任务
            List<String> assignees = resolveAssignees(nextNode, instance.getVariables());
            taskRepository.createTasks(instance.getId(), nextNode, assignees);
            eventPublisher.publishEvent(new TaskPendingEvent(
                this, instance.getId(), instance.getProcessKey(), nextNode.getName(), assignees));
        }
    }
}

    }

    /** 审批通过 → 通知发起人 */
    @EventListener
    public void onTaskApproved(TaskApprovedEvent event) {
        ProcessInstance instance = instanceRepository.findById(event.getProcessInstanceId());
        notificationService.send(instance.getInitiatorId(), NotificationType.APPROVED,

    }

    /** 审批驳回 → 通知发起人 */
    @EventListener
    public void onTaskRejected(TaskRejectedEvent event) {

        notificationService.send(instance.getInitiatorId(), NotificationType.REJECTED,

            callback.onCompleted(event.getProcessInstanceId(), event.getResult(), event.getVariables());
        }
    }
}
```

### 场景 8：低代码 — 表单联动事件

```java
/**
 * 低代码平台：表单字段联动
 * 字段 A 的值改变 → 触发字段 B 的联动规则（显示/隐藏/重新加载选项等）
 */

// 字段值变更事件
public class FieldValueChangedEvent extends ApplicationEvent {
    private final String formId;
    private final String fieldId;
    private final Object oldValue;
    private final Object newValue;
    private final Map<String, Object> formContext;  // 整个表单当前值
    // constructor, getters...
}

// 联动规则处理器
@Component
public class FormLinkageHandler {

    @Autowired
    private LinkageRuleRepository ruleRepository;

    /**
     * 监听字段值变更，执行联动规则
     * 使用条件过滤，避免不相关的事件进入处理逻辑
     */
    @EventListener(condition = "#event.formId != null")
    public List<FieldAction> onFieldChanged(FieldValueChangedEvent event) {
        // 查找该字段关联的联动规则
        List<LinkageRule> rules = ruleRepository.findBySourceField(event.getFormId(), event.getFieldId());

        List<FieldAction> actions = new ArrayList<>();
        for (LinkageRule rule : rules) {
            // 评估规则条件（如：当"请假类型"="年假"时，"天数"字段最大值改为15）
            if (rule.evaluate(event.getFormContext())) {
                actions.addAll(rule.getActions());
            }
        }
```

```java
 * 审批流引擎：自动校验操作权限

// 自定义注解：标记需要权限校验的审批操作
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireApprovalPermission {
    ApprovalAction value();  // 审批/驳回/转办/加签/撤回
}

public enum ApprovalAction {
    APPROVE, REJECT, TRANSFER, ADD_SIGN, WITHDRAW, URGE
}

@Aspect
@Component
@Order(Ordered.HIGHEST_PRECEDENCE)  // 最先执行（在事务之前）
public class ApprovalPermissionAspect {

    @Autowired
    private TaskRepository taskRepository;
    @Autowired
    private UserContext userContext;

    /**
     * 拦截所有标注了 @RequireApprovalPermission 的方法
     */
    @Before("@annotation(permission)")
    public void checkPermission(JoinPoint joinPoint, RequireApprovalPermission permission) {
        String currentUserId = userContext.getCurrentUserId();
        ApprovalAction action = permission.value();

        // 从方法参数中提取 taskId
        Object[] args = joinPoint.getArgs();
        String taskId = extractTaskId(args);

        ApprovalTask task = taskRepository.findById(taskId);
        if (task == null) {
            throw new ApprovalException("任务不存在: " + taskId);
        }

        // 权限校验
        switch (action) {
            case APPROVE, REJECT -> {
                // 只有任务指定的审批人才能审批/驳回
                if (!task.getAssigneeIds().contains(currentUserId)) {
                    throw new NoPermissionException("您不是该任务的审批人，无法执行" + action.getDisplayName());
                }
                // 任务必须是待审批状态
                if (task.getStatus() != TaskStatus.PENDING) {
                    throw new ApprovalException("该任务已" + task.getStatus().getDisplayName() + "，无法重复操作");
                }
            }
            case WITHDRAW -> {
                // 只有发起人才能撤回，且流程未结束
                ProcessInstance instance = instanceRepository.findById(task.getProcessInstanceId());
                if (!instance.getInitiatorId().equals(currentUserId)) {
                    throw new NoPermissionException("只有发起人才能撤回流程");
                }
                if (instance.getStatus() == ProcessStatus.COMPLETED) {
                    throw new ApprovalException("流程已结束，无法撤回");
                }
            }
            case TRANSFER -> {
                // 只有当前审批人才能转办
                if (!task.getAssigneeIds().contains(currentUserId)) {
                    throw new NoPermissionException("只有当前审批人才能转办任务");
                }
            }
        }
    }

    private String extractTaskId(Object[] args) {
        for (Object arg : args) {
            if (arg instanceof String s && s.startsWith("TASK_")) return s;
            if (arg instanceof ApprovalRequest req) return req.getTaskId();
        }
        throw new IllegalArgumentException("方法参数中未找到 taskId");
    }
}
```

```java
@Aspect
@Component
public class AuditLogAspect {

    @Autowired
    private AuditLogService auditLogService;
    @Autowired
    private UserContext userContext;

    @Around("@annotation(auditLog)")
    public Object recordAuditLog(ProceedingJoinPoint joinPoint, AuditLog auditLog) throws Throwable {

        Object[] args = joinPoint.getArgs();
        Map<String, Object> beforeSnapshot = captureSnapshot(auditLog.module(), args);

        Object result = null;

            // 2. 执行目标方法
            result = joinPoint.proceed();
            return result;
        } catch (Throwable ex) {
            error = ex;
            throw ex;
        } finally {

            Map<String, Object> afterSnapshot = error == null
                ? captureSnapshot(auditLog.module(), args)
                : null;

            AuditLogEntry entry = AuditLogEntry.builder()
                .module(auditLog.module())
                .operation(auditLog.operation())
                .description(auditLog.description())
                .operatorId(userContext.getCurrentUserId())
                .operatorName(userContext.getCurrentUserName())
                .tenantId(userContext.getTenantId())
                .timestamp(LocalDateTime.now())
                .duration(duration)
                .success(error == null)
                .errorMessage(error != null ? error.getMessage() : null)
                .beforeData(JsonUtils.toJson(beforeSnapshot))
                .afterData(JsonUtils.toJson(afterSnapshot))
                .methodSignature(joinPoint.getSignature().toShortString())
                .requestArgs(JsonUtils.toJson(args))
                .build();

        }
    }
```

```java
/**
 * 审批流引擎：审批通过 → 回写业务系统
 * 利用事务传播行为确保「审批记录」和「业务数据变更」的一致性

@Service
public class ApprovalCallbackService {

    @Autowired
    private TransactionTemplate transactionTemplate;
    @Autowired
    private ApplicationEventPublisher eventPublisher;

    /**
     * 审批通过后的回调处理
     * 场景：请假审批通过 → 扣减假期余额 + 更新考勤系统 + 发通知
     *
     * 核心问题：审批记录和业务数据必须在同一事务中，
     *          但通知发送（邮件/钉钉）不应该在事务内（避免超时）
     */
    @Transactional(rollbackFor = Exception.class)
    public void onLeaveApproved(String processInstanceId) {
        ProcessInstance instance = instanceRepository.findById(processInstanceId);
        Map<String, Object> formData = instance.getVariables();

        String userId = (String) formData.get("applicantId");
        int leaveDays = (int) formData.get("leaveDays");
        String leaveType = (String) formData.get("leaveType");

        // 1. 更新审批记录状态（主事务）
        instance.complete(ProcessResult.APPROVED);
        instanceRepository.save(instance);

        // 2. 扣减假期余额（同一事务，REQUIRED 传播行为）
        leaveBalanceService.deduct(userId, leaveType, leaveDays);

        // 3. 创建考勤记录（同一事务）
        attendanceService.createLeaveRecord(userId,
            (LocalDate) formData.get("startDate"),
            (LocalDate) formData.get("endDate"),
            leaveType);

        // 4. 事务提交后再发通知（利用 TransactionSynchronization）
        TransactionSynchronizationManager.registerSynchronization(
            new TransactionSynchronization() {
                @Override
                public void afterCommit() {
                    // 事务已提交，数据已持久化，安全发送通知
                    eventPublisher.publishEvent(new ProcessCompletedEvent(
                        this, processInstanceId, "leave_apply", ProcessResult.APPROVED));
                }
            });
    }

    /**
     * 费用报销审批通过 → 创建付款单
     * 场景：报销金额 > 5万，付款单需要财务二次确认
     *
     * 使用 REQUIRES_NEW：付款单创建失败不应影响审批记录
     */
    @Transactional(rollbackFor = Exception.class)
    public void onExpenseApproved(String processInstanceId) {
        ProcessInstance instance = instanceRepository.findById(processInstanceId);

        // 1. 更新审批状态（主事务）
        instance.complete(ProcessResult.APPROVED);
        instanceRepository.save(instance);

        // 2. 创建付款单（新事务：REQUIRES_NEW）
        // 即使付款单创建失败，审批记录仍然有效
        try {
            paymentService.createPaymentOrder(instance.getVariables());
        } catch (Exception e) {
            log.error("付款单创建失败，流程实例: {}", processInstanceId, e);
            // 记录异常，后续人工处理
            exceptionRecordService.record(processInstanceId, "付款单创建失败", e.getMessage());
        }
    }
}

public class PaymentService {

    /**
     * REQUIRES_NEW：在独立事务中创建付款单
     * 即使调用方回滚，付款单事务独立提交/回滚

        if (amount.compareTo(new BigDecimal("50000")) > 0) {
            order.setStatus(PaymentStatus.PENDING_FINANCE_CONFIRM);
        } else {
            order.setStatus(PaymentStatus.PENDING_PAYMENT);
        }

        return paymentOrderRepository.save(order);
    }
```

```java
/**
 * 审批流引擎：会签场景的事务处理
 * 会签：多人同时审批，需要全部通过（或达到比例）才算通过
 *
 * 并发问题：多个审批人可能同时操作，需要考虑事务隔离和乐观锁
 */
@Service
public class CountersignService {

    /**
     * 会签审批操作
     * 使用乐观锁防止并发冲突
     */
    @Transactional(rollbackFor = Exception.class, isolation = Isolation.READ_COMMITTED)
    public void approveInCountersign(String taskId, String approverId, String comment) {
        // 1. 获取并锁定当前任务（乐观锁）
        ApprovalTask task = taskRepository.findByIdWithOptimisticLock(taskId);
        if (task.getStatus() != TaskStatus.PENDING) {
            throw new ApprovalException("该任务已处理");
        }

        // 2. 记录当前人的审批结果
        task.recordApproval(approverId, ApprovalResult.APPROVED, comment);
        taskRepository.save(task);  // @Version 字段防止并发覆盖

        // 3. 检查会签条件
        CountersignConfig config = task.getCountersignConfig();
        int totalCount = config.getTotalAssignees();
        int approvedCount = task.getApprovedCount();
        int rejectedCount = task.getRejectedCount();

        boolean shouldComplete = switch (config.getStrategy()) {
            case ALL_APPROVE -> approvedCount == totalCount;            // 全部通过
            case RATIO -> approvedCount >= totalCount * config.getPassRatio();  // 达到比例
            case ONE_REJECT -> rejectedCount > 0;                      // 一票否决
            case ALL_VOTED -> (approvedCount + rejectedCount) == totalCount;   // 全部投票完成
        };

        if (shouldComplete) {
            // 4. 会签完成，推进流程
            ProcessResult result = (rejectedCount == 0 || approvedCount >= totalCount * config.getPassRatio())
                ? ProcessResult.APPROVED
                : ProcessResult.REJECTED;

            advanceProcess(task.getProcessInstanceId(), task.getNodeId(), result);
        }
    }
}
```

```java
/**
 * 低代码平台：表单提交涉及多个外部系统
 * 保存表单数据 + 同步到 ES + 触发工作流 + 发通知
 * 使用事务 + 补偿机制确保数据一致性

@Service
public class FormSubmitService {

    @Autowired
    private PlatformTransactionManager transactionManager;

    /**
     * 表单提交：核心数据在事务内，非核心操作在事务外（带补偿）
     */
    public FormSubmitResult submit(String formId, Map<String, Object> formData, String userId) {
        TransactionTemplate txTemplate = new TransactionTemplate(transactionManager);

        // 第一阶段：事务内 — 保存核心数据
        String recordId = txTemplate.execute(status -> {
            try {
                // 1. 校验表单数据
                validate(formId, formData);

                // 2. 保存表单数据
                String id = formDataRepository.save(formId, formData, userId);

                // 3. 保存操作日志
                operationLogRepository.save(formId, id, "SUBMIT", userId);

                return id;
            } catch (ValidationException e) {
                status.setRollbackOnly();
                throw e;
            }
        });

        // 第二阶段：事务外 — 非核心操作（带重试和补偿）
        CompletableFuture.runAsync(() -> {
            // 同步到 ES（失败会重试）
            retryTemplate.execute(ctx -> {
                esService.index(formId, recordId, formData);
                return null;
            });
        });

        CompletableFuture.runAsync(() -> {
            // 触发关联的审批流程
            try {
                approvalEngine.startProcess(formId, userId, formData);
            } catch (Exception e) {
                // 记录失败，由定时任务补偿
                compensationTaskRepository.save(new CompensationTask(
                    "START_PROCESS", formId, recordId, formData, e.getMessage()));
            }
        });

        return new FormSubmitResult(recordId, true);
    }
}
```

```java
            .map(e -> new FieldError(e.getFieldId(), e.getFieldLabel(), e.getMessage()))

        return ApiResponse.fail("FORM_VALIDATION_ERROR", "表单校验失败", fieldErrors);
    }

    /**
     * 审批流程异常
     */
    @ExceptionHandler(ApprovalException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiResponse<?> handleApproval(ApprovalException ex) {
        return ApiResponse.fail("APPROVAL_ERROR", ex.getMessage());
    }

    /**
     * 流程定义不合法
     */
    @ExceptionHandler(InvalidProcessDefinitionException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiResponse<?> handleInvalidProcess(InvalidProcessDefinitionException ex) {
        return ApiResponse.fail("INVALID_PROCESS", "流程定义错误: " + ex.getMessage());
    }

    /**
     * 权限不足
     */
    @ExceptionHandler(NoPermissionException.class)
    @ResponseStatus(HttpStatus.FORBIDDEN)
    public ApiResponse<?> handleNoPermission(NoPermissionException ex) {
        return ApiResponse.fail("NO_PERMISSION", ex.getMessage());
    }

    /**
     * 租户不存在或已过期
     */
    @ExceptionHandler(TenantException.class)
    @ResponseStatus(HttpStatus.FORBIDDEN)
    public ApiResponse<?> handleTenant(TenantException ex) {
        return ApiResponse.fail("TENANT_ERROR", "租户异常: " + ex.getMessage());
    }

    /**
     * 乐观锁冲突（并发审批）
     */
    @ExceptionHandler(OptimisticLockingFailureException.class)
    @ResponseStatus(HttpStatus.CONFLICT)
    public ApiResponse<?> handleOptimisticLock(OptimisticLockingFailureException ex) {
        return ApiResponse.fail("CONCURRENT_CONFLICT", "操作冲突，请刷新后重试");
    }

    /**
     * 拦截器：记录所有 API 调用耗时
     */
    @Component
    public static class ApiPerformanceInterceptor implements HandlerInterceptor {

        @Override
        public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
            request.setAttribute("_startTime", System.currentTimeMillis());
            return true;
        }

        @Override
        public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                Object handler, Exception ex) {
            long start = (long) request.getAttribute("_startTime");
            long duration = System.currentTimeMillis() - start;

            if (duration > 3000) {
                log.warn("慢接口告警: {} {} 耗时 {}ms", request.getMethod(), request.getRequestURI(), duration);
            }

            // 上报 metrics
            Metrics.timer("api.request.duration",
                "method", request.getMethod(),
                "uri", request.getRequestURI(),
                "status", String.valueOf(response.getStatus()))
                .record(Duration.ofMillis(duration));
        }
    }
}
```

### 场景 18：审批流 — SSE 实时审批进度推送

```java
/**
 * 审批流引擎：使用 WebFlux SSE 推送审批进度
 * 用户打开审批详情页后，通过 SSE 实时接收审批状态更新
 */
@RestController
@RequestMapping("/api/approval/stream")
public class ApprovalStreamController {

    @Autowired
    private ApprovalEventBus eventBus;  // 基于 Reactor Sinks 的事件总线

    /**
     * SSE 端点：实时推送某个流程实例的审批进度
     * 用户打开审批详情页时订阅，页面关闭时自动取消
     */
    @GetMapping(value = "/process/{processInstanceId}", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<ApprovalUpdate>> streamProcessUpdates(
            @PathVariable String processInstanceId) {

        return eventBus.subscribe(processInstanceId)
            .map(update -> ServerSentEvent.<ApprovalUpdate>builder()
                .id(update.getEventId())
                .event(update.getEventType())  // "task_created" / "task_approved" / "process_completed"
                .data(update)
                .build())
            .doOnCancel(() -> log.info("客户端断开 SSE 连接: {}", processInstanceId));
    }

    /**
     * SSE 端点：推送当前用户的待办数量变化
     * 用于首页待办徽标实时更新
     */
    @GetMapping(value = "/my-pending-count", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<Integer>> streamPendingCount(@RequestHeader("X-User-Id") String userId) {

        // 每当有新任务分配或任务完成时推送
        return eventBus.subscribeUserPending(userId)
            .map(count -> ServerSentEvent.<Integer>builder()
                .event("pending_count")
                .data(count)
                .build())
            // 每 30 秒发送一次心跳，保持连接
            .mergeWith(Flux.interval(Duration.ofSeconds(30))
                .map(tick -> ServerSentEvent.<Integer>builder()
                    .event("heartbeat")
                    .comment("keep-alive")
                    .build()));
    }
}

/**
 * 审批事件总线：基于 Reactor Sinks 实现
 */
@Component
public class ApprovalEventBus {

    // 流程实例 → 事件流
    private final Map<String, Sinks.Many<ApprovalUpdate>> processSinks = new ConcurrentHashMap<>();
    // 用户 → 待办数变化流
    private final Map<String, Sinks.Many<Integer>> userPendingSinks = new ConcurrentHashMap<>();

    /**
     * 发布审批事件（由 ApprovalEngine 调用）
     */
    public void publish(String processInstanceId, ApprovalUpdate update) {
        Sinks.Many<ApprovalUpdate> sink = processSinks.get(processInstanceId);
        if (sink != null) {
            sink.tryEmitNext(update);
        }
    }

    /**
     * 更新用户待办数
     */
    public void updatePendingCount(String userId, int count) {
        Sinks.Many<Integer> sink = userPendingSinks.get(userId);
        if (sink != null) {
            sink.tryEmitNext(count);
        }
    }

    /**
     * 订阅流程更新
     */
    public Flux<ApprovalUpdate> subscribe(String processInstanceId) {
        return processSinks.computeIfAbsent(processInstanceId,
            k -> Sinks.many().multicast().onBackpressureBuffer())
            .asFlux()
            .doOnCancel(() -> processSinks.remove(processInstanceId));
    }

    /**
     * 订阅用户待办数变化
     */
    public Flux<Integer> subscribeUserPending(String userId) {
        return userPendingSinks.computeIfAbsent(userId,
            k -> Sinks.many().multicast().onBackpressureBuffer())
            .asFlux()
            .doOnCancel(() -> userPendingSinks.remove(userId));
    }
}
```

### 场景 19：低代码 — WebFlux 实现数据导出流式下载

```java
/**
 * 低代码平台：大数据量导出
 * 使用 WebFlux 流式输出，避免 OOM
 * 百万级数据导出不占用大量内存
 */
@RestController
@RequestMapping("/api/export")
public class DataExportController {

    @Autowired
    private DynamicDataService dataService;

    /**
     * 流式导出 CSV
     * 使用 Flux 逐行产生数据，背压控制内存使用
     */
    @GetMapping(value = "/models/{modelId}/csv", produces = "text/csv")
    public Mono<Void> exportCsv(
            @PathVariable String modelId,
            @RequestParam(required = false) String filter,
            ServerHttpResponse response) {

        ModelDefinition model = modelService.getModel(modelId);

        // 设置响应头
        response.getHeaders().setContentDisposition(
            ContentDisposition.attachment()
                .filename(model.getName() + "_" + LocalDate.now() + ".csv", StandardCharsets.UTF_8)
                .build());

        // CSV Header
        String header = model.getFields().stream()
            .map(FieldDefinition::getLabel)
            .collect(Collectors.joining(",")) + "\n";

        Flux<DataBuffer> dataStream = Flux.concat(
            // 1. 写入表头
            Mono.just(toBuffer(response, header)),

            // 2. 流式写入数据行（每次从数据库读取 500 条）
            dataService.streamQuery(model, parseFilter(filter), 500)
                .map(row -> {
                    String line = model.getFields().stream()
                        .map(field -> escapeCsv(row.get(field.getId())))
                        .collect(Collectors.joining(",")) + "\n";
                    return toBuffer(response, line);
                })
        );

        return response.writeWith(dataStream);
    }

    private DataBuffer toBuffer(ServerHttpResponse response, String content) {
        return response.bufferFactory().wrap(content.getBytes(StandardCharsets.UTF_8));
    }
}
```

### 场景 20：低代码 — WebClient 聚合多数据源

```java
/**
 * 低代码平台：仪表盘数据聚合
 * 一个仪表盘页面包含多个图表组件，每个组件的数据可能来自不同 API
 * 使用 WebFlux 并行调用，大幅降低整体延迟
 */
@Service
public class DashboardAggregationService {

    private final WebClient webClient;

    public DashboardAggregationService(WebClient.Builder builder) {
        this.webClient = builder.build();
    }

    /**
     * 聚合仪表盘所有组件的数据
     * 假设仪表盘有 5 个图表，每个数据源平均 200ms
     * 串行：5 × 200ms = 1000ms
     * 并行：max(200ms) ≈ 200ms
     */
    public Mono<DashboardData> aggregateDashboard(DashboardConfig config, String tenantId) {
        List<Mono<ComponentData>> componentMonos = config.getComponents().stream()
            .map(component -> fetchComponentData(component, tenantId)
                .onErrorResume(ex -> {
                    // 单个组件失败不影响整个仪表盘
                    log.warn("组件 {} 数据加载失败: {}", component.getId(), ex.getMessage());
                    return Mono.just(ComponentData.error(component.getId(), ex.getMessage()));
                })
                .timeout(Duration.ofSeconds(5))  // 单个组件超时 5 秒
            )
            .toList();

        return Flux.merge(componentMonos)
            .collectList()
            .map(components -> new DashboardData(config.getId(), components));
    }

    private Mono<ComponentData> fetchComponentData(ComponentConfig component, String tenantId) {
        return switch (component.getDataSourceType()) {
            case INTERNAL_API -> webClient.get()
                .uri(component.getApiUrl())
                .header("X-Tenant-Id", tenantId)
                .retrieve()
                .bodyToMono(Object.class)
                .map(data -> new ComponentData(component.getId(), data));

            case SQL_QUERY -> Mono.fromCallable(() ->
                    dynamicDataService.executeSql(component.getSqlQuery(), tenantId))
                .subscribeOn(Schedulers.boundedElastic())  // 阻塞 SQL 切到弹性线程池
                .map(data -> new ComponentData(component.getId(), data));

            case EXTERNAL_API -> webClient.get()
                .uri(component.getExternalUrl())
                .retrieve()
                .bodyToMono(Object.class)
                .map(data -> new ComponentData(component.getId(), data));

            default -> Mono.just(ComponentData.empty(component.getId()));
        };
    }
}
```

## 八、综合场景 — 低代码审批流完整架构

### 场景 21：低代码 + 审批流 — 完整业务流程

```java
/**
 * 综合场景：用户在低代码平台配置了一个"采购申请"表单和审批流程
 *
 * 涉及的 Spring 核心机制：
 * 1. IoC / DI — 组件装配、动态注册
 * 2. BeanPostProcessor — 自动发现处理器
 * 3. Event — 流程状态通知
 * 4. AOP — 权限校验、审计日志、多租户隔离
 * 5. Transaction — 数据一致性
 * 6. MVC — API 层、参数解析、异常处理
 * 7. WebFlux — 实时通知
 */

/**
 * 采购申请表单提交 + 触发审批流程
 * 一个请求涉及 Spring 的多个核心机制
 */
@RestController
@RequestMapping("/api/purchase")
public class PurchaseController {

    @Autowired private FormSubmitService formSubmitService;
    @Autowired private ApprovalEngine approvalEngine;

    /**
     * 提交采购申请
     *
     * 请求流经的 Spring 组件：
     *
     * 1. [MVC] DispatcherServlet → HandlerMapping → HandlerAdapter
     * 2. [MVC] @CurrentUser 参数解析器 → 自动注入当前用户
     * 3. [MVC] @RequestBody → Jackson MessageConverter 反序列化
     * 4. [AOP] TenantIsolationAspect → 设置租户上下文
     * 5. [AOP] AuditLogAspect → 记录操作日志
     * 6. [Transaction] @Transactional → 开启事务
     * 7. [IoC] FormSubmitService → 依赖注入
     * 8. [Event] ProcessStartedEvent → 通知监听器
     * 9. [Event] TaskPendingEvent → 触发消息通知
     * 10. [Transaction] afterCommit → 事务提交后发通知
     * 11. [WebFlux] SSE → 实时推送待办到审批人
     * 12. [MVC] @RestControllerAdvice → 统一异常处理
     */
    @PostMapping("/submit")
    @AuditLog(module = "采购申请", operation = "提交")
    public ApiResponse<SubmitResult> submitPurchase(
            @CurrentUser User currentUser,       // [MVC] 自定义参数解析器
            @Valid @RequestBody PurchaseForm form) {

        // [Transaction + Event] 保存表单 + 发起审批
        String recordId = formSubmitService.submit("purchase_form", form.toMap(), currentUser.getId());

        // [Transaction + Event] 启动审批流程
        String processId = approvalEngine.startProcess(
            "purchase_approval",       // 流程定义 key
            currentUser.getId(),       // 发起人
            Map.of(
                "recordId", recordId,
                "amount", form.getTotalAmount(),
                "department", currentUser.getDepartmentId(),
                "items", form.getItems()
            ));

        return ApiResponse.ok(new SubmitResult(recordId, processId));
    }
}
```

## 面试融合指南

### 如何在面试中结合业务讲 Spring 源码？

| 面试题 | 纯源码回答 | 结合业务回答 |
|--------|-----------|-------------|
| BeanFactoryPostProcessor 的作用？ | 在 Bean 实例化前修改 BeanDefinition | 低代码平台用它实现插件自动扫描，启动时发现所有 @LowCodeComponent 注解的类并注册 |
| BeanPostProcessor 的作用？ | 在 Bean 初始化前后做额外处理 | 审批流引擎用它自动发现并注册所有 FieldValidator，新增校验器只需加注解，零配置 |
| Spring 事件机制的使用场景？ | 解耦发布者和监听者 | 审批流用事件驱动通知：审批通过 → 站内信 + 邮件 + 业务回写，三个监听器完全解耦 |
| AOP 在项目中的应用？ | 日志、事务、权限 | 审批流用 AOP 做操作前的权限校验（只有审批人能审批），低代码用 AOP 做多租户数据隔离 |
| 事务传播行为 REQUIRES_NEW 的场景？ | 独立事务、不受外层影响 | 报销审批通过后创建付款单用 REQUIRES_NEW，付款单失败不影响审批记录 |
| TransactionSynchronization 的作用？ | 事务提交/回滚后的回调 | 审批通过并事务提交后才发通知，避免事务回滚但通知已发出的不一致 |
| 自定义 HandlerMapping 的场景？ | 动态路由 | 低代码平台用户创建数据模型后自动生成 CRUD API，通过自定义 HandlerMapping 动态路由 |
| WebFlux SSE 的场景？ | 服务端推送 | 审批详情页实时显示审批进度，有人审批通过时发起人页面实时更新 |
