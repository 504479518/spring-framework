# 从一个请求说起——Spring 全链路追踪

> 以一个真实业务场景「用户提交审批单」为例，追踪 HTTP 请求从浏览器发出到数据库落盘的完整链路。
> 每个环节标注 **核心类 + 关键方法 + 源码位置**，可直接打断点验证。

---

## 业务场景

```
POST /api/approval
Content-Type: application/json

{
    "title": "采购申请",
    "amount": 50000,
    "applicantId": 1001
}
```

预期行为：
1. 认证拦截器校验 Token
2. Controller 接收参数
3. AOP 日志切面记录操作
4. 事务中保存审批单 + 审批节点
5. 发布事件通知审批人
6. 返回 JSON 响应

---

## 关键断点速查表

| 序号 | 环节 | 类 | 方法 | 要观察的变量 |
|------|------|-----|------|------------|
| 1 | 请求入口 | DispatcherServlet | doDispatch() | request.getRequestURI() |
| 2 | Handler 查找 | RequestMappingHandlerMapping | getHandlerInternal() | lookupPath, bestMatch |
| 3 | 拦截器前置 | HandlerInterceptor | preHandle() | request headers |
| 4 | 参数解析 | RequestResponseBodyMethodProcessor | resolveArgument() | 反序列化后的 DTO |
| 5 | AOP 拦截器链 | ReflectiveMethodInvocation | proceed() | currentInterceptorIndex |
| 6 | 事务创建 | AbstractPlatformTransactionManager | getTransaction() | definition, transaction |
| 7 | SQL 执行 | DataSourceUtils | getConnection() | ThreadLocal 中的连接 |
| 8 | 事务提交 | AbstractPlatformTransactionManager | processCommit() | status |
| 9 | 返回值序列化 | MappingJackson2HttpMessageConverter | writeInternal() | 序列化后的 JSON |
| 10 | 拦截器完成 | HandlerInterceptor | afterCompletion() | exception（如有） |

## 异常场景链路

当业务代码抛出异常时，链路变化如下：

```
目标方法抛出 RuntimeException
  ↑
TransactionInterceptor 捕获
  → completeTransactionAfterThrowing()
  → rollbackOn(ex) = true
  → connection.rollback() ❌ 回滚
  → 重新抛出异常
  ↑
LogAspect（@Around）
  → catch 到异常
  → log.error("执行失败", ex)
  → 重新抛出异常
  ↑
DispatcherServlet.doDispatch()
  → dispatchException = ex
  → processDispatchResult()
  → processHandlerException()
  → @ExceptionHandler 或 @ControllerAdvice 处理
  → 返回错误 JSON：{"code": 500, "message": "..."}
```

## 线程模型

```
┌─────────────────────────────────────────┐
│           Tomcat 线程池                  │
│  ┌─────────────────────────────────┐    │
│  │  http-nio-8080-exec-1           │    │
│  │                                 │    │
│  │  ThreadLocal 中绑定的内容：       │    │
│  │  ├── RequestAttributes          │    │
│  │  ├── TransactionInfo            │    │
│  │  ├── ConnectionHolder（事务连接） │    │
│  │  ├── TransactionSynchronization │    │
│  │  └── SecurityContext            │    │
│  │                                 │    │
│  │  整个请求在同一个线程中执行！      │    │
│  │  所以 ThreadLocal 在请求内有效。  │    │
│  └─────────────────────────────────┘    │
│                                         │
│  ⚠️ 注意：@Async 方法会切换线程！        │
│     ThreadLocal 中的数据会丢失！         │
│     事务不会传播到异步线程！             │
└─────────────────────────────────────────┘
```
