# Spring 面试对比表格汇总

> 把容易混淆的概念做成对比表格，面试前速查，源码阅读时对照理解。

## 一、事务传播行为对比（七种）

> 源码位置：[AbstractPlatformTransactionManager.getTransaction()](file:///Users/hefei/github/java/spring-framework/spring-tx/src/main/java/org/springframework/transaction/support/AbstractPlatformTransactionManager.java#L376)

| 传播行为 | 当前无事务 | 当前有事务 | 典型场景 |
|----------|-----------|-----------|---------|
| **REQUIRED**（默认） | 新建事务 | 加入当前事务 | 大多数业务方法 |
| **REQUIRES_NEW** | 新建事务 | **挂起**当前事务，新建独立事务 | 操作日志、审批流日志（不随业务回滚） |
| **NESTED** | 新建事务 | 在当前事务中创建 **Savepoint** | 批量导入（单条失败不影响整批） |
| **SUPPORTS** | 非事务执行 | 加入当前事务 | 只读查询（有事务就用，没有也行） |
| **NOT_SUPPORTED** | 非事务执行 | **挂起**当前事务，非事务执行 | 不需要事务的辅助操作 |
| **MANDATORY** | ❌ 抛异常 | 加入当前事务 | 强制要求调用方已开启事务 |
| **NEVER** | 非事务执行 | ❌ 抛异常 | 强制禁止在事务中调用 |

### 重点对比：REQUIRED vs REQUIRES_NEW vs NESTED

| 维度 | REQUIRED | REQUIRES_NEW | NESTED |
|------|----------|-------------|--------|
| 是否共用连接 | ✅ 同一个连接 | ❌ 新连接 | ✅ 同一个连接 |
| 内层回滚对外层的影响 | 外层也回滚（globalRollbackOnly） | 互不影响 | 只回滚到 Savepoint，外层不受影响 |
| 外层回滚对内层的影响 | 一起回滚 | 内层已独立提交，不回滚 | 一起回滚 |
| 实现机制 | 直接参与 | suspend + doBegin | JDBC Savepoint |
| 性能开销 | 最低 | 较高（新连接） | 中等 |

## 二、BeanFactory vs ApplicationContext

| 维度 | BeanFactory | ApplicationContext |
|------|------------|-------------------|
| 定位 | IoC 容器的基础接口 | BeanFactory 的超集，企业级容器 |
| Bean 创建时机 | **懒加载**（getBean 时才创建） | **预实例化**（refresh 时创建所有单例） |
| 事件机制 | ❌ 不支持 | ✅ ApplicationEvent / ApplicationListener |
| 国际化 | ❌ 不支持 | ✅ MessageSource |
| 资源加载 | ❌ 不支持 | ✅ ResourceLoader |
| AOP 自动代理 | 需手动配置 | 自动注册 BeanPostProcessor |
| 常用实现类 | DefaultListableBeanFactory | AnnotationConfigApplicationContext |
| 源码位置 | spring-beans 模块 | spring-context 模块 |

## 三、JDK 动态代理 vs CGLIB

> 源码位置：[DefaultAopProxyFactory.createAopProxy()](file:///Users/hefei/github/java/spring-framework/spring-aop/src/main/java/org/springframework/aop/framework/DefaultAopProxyFactory.java)

| 维度 | JDK 动态代理 | CGLIB |
|------|------------|-------|
| 原理 | 基于接口，实现 InvocationHandler | 基于继承，生成目标类的子类 |
| 要求 | 目标类**必须实现接口** | 目标类**不能是 final** |
| 代理对象类型 | 接口类型（$Proxy0） | 子类类型（UserService$$EnhancerBySpringCGLIB） |
| 性能 | 方法调用通过反射，稍慢 | 生成字节码直接调用，方法调用稍快 |
| Spring Boot 默认 | ❌ | ✅（2.0+ 默认 proxyTargetClass=true） |
| final 方法 | 代理接口方法，无此问题 | **无法代理 final 方法**（不会报错但不生效） |

### Spring 的选择策略

```
if (目标类实现了接口 && 未强制 proxyTargetClass) {
    使用 JDK 动态代理
} else {
    使用 CGLIB
}
```

## 四、@Autowired vs @Resource vs @Inject

| 维度 | @Autowired | @Resource | @Inject |
|------|-----------|----------|---------|
| 来源 | Spring 专有 | JSR-250（Java 标准） | JSR-330（Java 标准） |
| 默认注入方式 | **按类型** | **按名称** | **按类型** |
| 是否支持 required=false | ✅ | ❌ | ❌ |
| 搭配限定符 | @Qualifier | name 属性 | @Named |
| 处理器 | AutowiredAnnotationBeanPostProcessor | CommonAnnotationBeanPostProcessor | AutowiredAnnotationBeanPostProcessor |
| 可用位置 | 字段、构造器、方法 | 字段、方法（不能用于构造器） | 字段、构造器、方法 |

### 注入优先级

```
@Autowired 查找顺序：类型 → @Qualifier → @Primary → beanName
@Resource 查找顺序：name → 类型 → @Qualifier
```

## 五、Bean 作用域对比

| 作用域 | 实例数 | 生命周期 | 适用场景 |
|--------|-------|---------|---------|
| **singleton**（默认） | 整个容器 1 个 | 随容器创建和销毁 | 无状态 Service、DAO |
| **prototype** | 每次 getBean 新建 | 容器只负责创建，不管理销毁 | 有状态对象 |
| **request** | 每个 HTTP 请求 1 个 | 请求开始 → 请求结束 | Web 请求相关数据 |
| **session** | 每个 HTTP Session 1 个 | Session 创建 → Session 销毁 | 用户会话数据 |
| **application** | 每个 ServletContext 1 个 | 应用启动 → 应用关闭 | 全局共享配置 |

### 常见坑：singleton 注入 prototype

```java
@Component
public class SingletonService {
    @Autowired
    private PrototypeBean proto; // ❌ 只注入一次！后续都是同一个对象
}
```

**解决方案**：
1. `@Lookup` 方法注入
2. `ObjectFactory<PrototypeBean>` / `Provider<PrototypeBean>`
3. `applicationContext.getBean(PrototypeBean.class)`

## 六、BeanPostProcessor vs BeanFactoryPostProcessor

| 维度 | BeanPostProcessor | BeanFactoryPostProcessor |
|------|-------------------|-------------------------|
| 执行时机 | **每个 Bean** 初始化前后 | **BeanFactory** 标准初始化后、Bean 创建前 |
| 操作对象 | Bean **实例** | Bean **定义**（BeanDefinition） |
| 回调方法 | postProcessBeforeInitialization<br/>postProcessAfterInitialization | postProcessBeanFactory |
| 典型实现 | AutowiredAnnotationBeanPostProcessor<br/>AbstractAutoProxyCreator | ConfigurationClassPostProcessor<br/>PropertySourcesPlaceholderConfigurer |
| 作用 | 依赖注入、AOP 代理创建 | 注解扫描、占位符替换、BeanDefinition 修改 |

### 执行顺序

```
① BeanFactoryPostProcessor（修改 BeanDefinition）
    └── ConfigurationClassPostProcessor 解析 @Configuration
② BeanPostProcessor 注册（只注册，不执行）
③ Bean 创建时依次调用 BeanPostProcessor
    ├── postProcessBeforeInitialization
    ├── 初始化方法（@PostConstruct / afterPropertiesSet）
    └── postProcessAfterInitialization（AOP 在此创建代理）
```

## 七、@Configuration vs @Component

| 维度 | @Configuration | @Component |
|------|---------------|-----------|
| CGLIB 代理 | ✅ 默认生成代理类 | ❌ 普通类 |
| @Bean 方法调用 | 走代理，**保证单例** | 普通方法调用，**每次新建** |
| 内部 @Bean 互调 | 返回容器中的单例 | 返回新对象（非容器管理） |
| proxyBeanMethods | 默认 true（Full 模式） | 可设为 false（Lite 模式） |

```java
@Configuration
public class AppConfig {
    @Bean
    public ServiceA serviceA() {
        return new ServiceA(serviceB()); // 走代理 → 返回容器中的 serviceB 单例
    }
    @Bean
    public ServiceB serviceB() {
        return new ServiceB();
    }
}

@Component  // 换成 @Component
public class AppConfig {
    @Bean
    public ServiceA serviceA() {
        return new ServiceA(serviceB()); // ❌ 直接调用 → 每次 new 一个 ServiceB
    }
}
```

## 八、Spring 事件 vs 观察者模式 vs MQ

| 维度 | ApplicationEvent | 观察者模式 | MQ（RabbitMQ/Kafka） |
|------|-----------------|----------|---------------------|
| 范围 | JVM 进程内 | JVM 进程内 | 跨进程/跨服务 |
| 同步/异步 | 默认同步，可配置 @Async | 同步 | 异步 |
| 持久化 | ❌ | ❌ | ✅ |
| 可靠性 | 低（应用重启丢失） | 低 | 高（确认机制） |
| 耦合度 | 松耦合 | 松耦合 | 最松耦合 |
| 适用场景 | 容器生命周期事件、本地通知 | 简单回调 | 分布式事件驱动 |

## 九、三级缓存对比

> 源码位置：[DefaultSingletonBeanRegistry](file:///Users/hefei/github/java/spring-framework/spring-beans/src/main/java/org/springframework/beans/factory/support/DefaultSingletonBeanRegistry.java)

| 缓存 | 字段名 | 类型 | 存储内容 | 何时放入 | 何时移除 |
|------|--------|------|---------|---------|---------|
| 一级缓存 | singletonObjects | ConcurrentHashMap | **完全初始化**的单例 Bean | addSingleton()（Bean 创建完成） | destroySingleton() |
| 二级缓存 | earlySingletonObjects | ConcurrentHashMap | **提前暴露**的早期引用（可能是代理） | getSingleton() 时从三级缓存升级 | addSingleton() 时清除 |
| 三级缓存 | singletonFactories | HashMap | **ObjectFactory** 回调 | addSingletonFactory()（实例化后、属性注入前） | 升级到二级缓存后清除 |

### 为什么需要三级缓存而不是两级？

| 场景 | 两级缓存 | 三级缓存 |
|------|---------|---------|
| 无 AOP 的循环依赖 | ✅ 能解决 | ✅ 能解决 |
| 有 AOP 的循环依赖 | ❌ 实例化后就必须创建代理，<br/>打破了「代理在初始化后创建」的设计 | ✅ 按需创建代理：<br/>有循环依赖时提前创建，<br/>无循环依赖时正常创建 |
