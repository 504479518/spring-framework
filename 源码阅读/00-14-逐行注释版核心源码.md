## 一、容器启动 — refresh()

> 文件：`AbstractApplicationContext.java`
> 断点位置：`org.springframework.context.support.AbstractApplicationContext#refresh`

```java
// === AbstractApplicationContext.java ===
// 这是 Spring 容器启动的总入口，所有的 Bean 注册、实例化、初始化都从这里开始
// 你在 main() 中写 new AnnotationConfigApplicationContext(AppConfig.class) 时，最终就是调用这个方法
public void refresh() throws BeansException, IllegalStateException {

    // 获取启动/关闭锁，防止多个线程同时调用 refresh()
    // 如果两个线程同时 refresh，可能导致 BeanFactory 状态混乱
    this.startupShutdownLock.lock();

    try {
        // 记录当前线程，后续 close() 时会检查是否是同一个线程
        this.startupShutdownThread = Thread.currentThread();

        // 记录启动步骤（用于 Spring Boot 的启动耗时分析，不影响功能）
        StartupStep contextRefresh = this.applicationStartup.start("spring.context.refresh");

        // ============ 第 1 步：准备刷新 ============
        // 设置容器启动时间戳（System.currentTimeMillis()）
        // 设置 active=true, closed=false 标志位
        // 调用 initPropertySources()：让子类有机会初始化自定义属性源
        //   例如 Web 环境下会把 servletContext 参数注册为属性源
        // 调用 getEnvironment().validateRequiredProperties()：校验必须的环境变量
        // 初始化早期事件集合 earlyApplicationEvents（容器还没准备好时的事件先存这里）
        prepareRefresh();

        // ============ 第 2 步：获取 BeanFactory ============
        // 对于 AnnotationConfigApplicationContext（继承 GenericApplicationContext）：
        //   直接返回构造器中已经创建好的 DefaultListableBeanFactory 实例
        //   this.beanFactory 在 new GenericApplicationContext() 时就创建了
        // 对于 ClassPathXmlApplicationContext（继承 AbstractRefreshableApplicationContext）：
        //   会销毁旧的 BeanFactory，创建新的，然后加载 XML 中的 BeanDefinition
        ConfigurableListableBeanFactory beanFactory = obtainFreshBeanFactory();

        // ============ 第 3 步：配置 BeanFactory 的标准特性 ============
        // 注册类加载器（用于后续加载 Bean 的 Class）
        // 注册 SpEL 表达式解析器（让 @Value("#{...}") 生效）
        // 注册属性编辑器（用于类型转换，如 String → Date）
        // 注册 ApplicationContextAwareProcessor（处理各种 Aware 接口回调）
        // 忽略某些 Aware 接口的自动注入（因为由上面的 Processor 统一处理）
        // 注册可解析的依赖：@Autowired BeanFactory → 注入容器自身
        // 注册环境相关的单例：environment、systemProperties、systemEnvironment
        prepareBeanFactory(beanFactory);

        try {
            // ============ 第 4 步：子类扩展点 ============
            // 空方法，让子类覆写来对 BeanFactory 做额外配置
            // 例如：Web 环境下的 GenericWebApplicationContext 会在这里
            //   注册 request、session 作用域
            //   注册 ServletRequest、HttpSession 等可解析依赖
            postProcessBeanFactory(beanFactory);

            // ============ 第 5 步：调用所有 BeanFactoryPostProcessor ============
            // 这是最关键的一步之一！
            // 委托给 PostProcessorRegistrationDelegate 执行
            // 执行顺序：
            //   1. BeanDefinitionRegistryPostProcessor（可以注册新的 BeanDefinition）
            //      a. 实现 PriorityOrdered 的先执行
            //      b. 实现 Ordered 的其次
            //      c. 其余的最后
            //   2. BeanFactoryPostProcessor（只能修改已有的 BeanDefinition）
            //      a/b/c 同上
            //
            // 重点：ConfigurationClassPostProcessor 就是在这里执行的！
            //   它负责解析 @Configuration、@ComponentScan、@Bean、@Import 等所有注解
            //   解析完成后，容器中就有了所有业务 Bean 的 BeanDefinition
            invokeBeanFactoryPostProcessors(beanFactory);

            // ============ 第 6 步：注册 BeanPostProcessor ============
            // 注意：这里只是"注册"，不是"调用"！
            // 从 BeanFactory 中找出所有 BeanPostProcessor 类型的 BeanDefinition
            // 实例化它们（getBean），然后按优先级排序注册到 BeanFactory 的处理器列表中
            // 注册顺序：PriorityOrdered → Ordered → 普通 → MergedBeanDefinitionPostProcessor
            //
            // 常见的 BeanPostProcessor：
            //   - AutowiredAnnotationBeanPostProcessor（处理 @Autowired）
            //   - CommonAnnotationBeanPostProcessor（处理 @PostConstruct、@PreDestroy）
            //   - AbstractAutoProxyCreator（创建 AOP 代理）
            registerBeanPostProcessors(beanFactory);

            // ============ 第 7 步：初始化 MessageSource（国际化） ============
            // 如果容器中没有名为 "messageSource" 的 Bean，就创建一个默认的
            // 用于支持 getMessage() 国际化功能
            initMessageSource();

            // ============ 第 8 步：初始化事件广播器 ============
            // 如果容器中没有名为 "applicationEventMulticaster" 的 Bean
            // 就创建一个 SimpleApplicationEventMulticaster
            // 这个广播器负责将事件分发给所有匹配的监听器
            initApplicationEventMulticaster();

            // ============ 第 9 步：子类扩展点（onRefresh） ============
            // 空方法，让子类在 Bean 实例化之前做特殊处理
            // Spring Boot 在这里创建嵌入式 Web 服务器（Tomcat/Jetty/Undertow）
            //   具体是 ServletWebServerApplicationContext.onRefresh()
            //   → createWebServer() → new TomcatWebServer()
            onRefresh();

            // ============ 第 10 步：注册事件监听器 ============
            // 1. 将实现了 ApplicationListener 接口的 Bean 注册到广播器
            // 2. 将之前缓存的早期事件（earlyApplicationEvents）发布出去
            //    早期事件是在广播器还没初始化时产生的事件
            registerListeners();

            // ============ 第 11 步：实例化所有非懒加载的单例 Bean ============
            // 这是最耗时的一步！你的所有业务 Bean 都在这里创建
            // 内部调用 DefaultListableBeanFactory.preInstantiateSingletons()
            //   遍历所有 beanDefinitionNames
            //   对每个非懒加载、非抽象、单例的 BeanDefinition 调用 getBean(beanName)
            //   getBean() → doGetBean() → createBean() → doCreateBean()
            //   这条链路就是 Bean 创建的核心流程（见下一节）
            //
            // 完成后还会触发 SmartInitializingSingleton.afterSingletonsInstantiated()
            //   @EventListener 注解就是在这个回调中被解析注册的
            finishBeanFactoryInitialization(beanFactory);

            // ============ 第 12 步：完成刷新 ============
            // 清除资源缓存（ASM 元数据等）
            // 初始化 LifecycleProcessor，调用 onRefresh()（启动 SmartLifecycle Bean）
            // 发布 ContextRefreshedEvent 事件（通知所有监听器容器已启动）
            // 如果有 LiveBeansView 的 MBean 注册，参与 JMX 监控
            finishRefresh();

        } catch (RuntimeException | Error ex) {
            // 启动失败！

            // 销毁已经创建的 Bean（调用 @PreDestroy、DisposableBean.destroy()）
            destroyBeans();
            // 将 active 标志设为 false
            cancelRefresh(ex);
            // 将异常抛出，应用启动失败
            throw ex;
        } finally {
            // 结束启动步骤记录
            contextRefresh.end();
        }
    } finally {
        // 清除当前线程标记
        this.startupShutdownThread = null;
        // 释放锁
        this.startupShutdownLock.unlock();
    }
}
```

### AnnotationConfigApplicationContext 构造器

> 文件：`AnnotationConfigApplicationContext.java`

```java
// === AnnotationConfigApplicationContext.java ===
// 这是最常用的容器实现类，用于纯注解配置（不用 XML）
// 用法：new AnnotationConfigApplicationContext(AppConfig.class)

// 带参构造器：传入配置类，自动完成全部启动流程
public AnnotationConfigApplicationContext(Class<?>... componentClasses) {

    // 第一步：调用无参构造器
    // 会触发整个继承链的构造器：
    //   AnnotationConfigApplicationContext()
    //     → GenericApplicationContext()  ← 在这里创建 DefaultListableBeanFactory
    //       → AbstractApplicationContext()
    //         → DefaultResourceLoader()
    this();

    // 第二步：将传入的配置类（如 AppConfig.class）注册为 BeanDefinition
    // 内部调用 AnnotatedBeanDefinitionReader.register()
    // 将 AppConfig 包装成 AnnotatedGenericBeanDefinition，注册到 BeanFactory
    // 此时只注册了配置类本身，@ComponentScan 扫描到的类还没注册
    register(componentClasses);

    // 第三步：刷新容器（见上面的 refresh() 详解）
    // 这一步完成后，所有 Bean 都已经创建好了
    refresh();
}

// 无参构造器：只做准备工作，不触发容器刷新
public AnnotationConfigApplicationContext() {

    // 隐式调用父类 GenericApplicationContext 的无参构造器
    // GenericApplicationContext() {
    //     this.beanFactory = new DefaultListableBeanFactory();
    //     ← 这里创建了 Spring 的核心容器！
    //     ← DefaultListableBeanFactory 就是存放所有 BeanDefinition 和 Bean 实例的地方
    // }

    // 创建「注解 Bean 定义读取器」
    // 作用：读取 @Configuration、@Component 等注解，将类注册为 BeanDefinition
    // 构造器内部会注册一些 Spring 内部的基础设施 Bean：
    //   - ConfigurationClassPostProcessor（解析 @Configuration）
    //   - AutowiredAnnotationBeanPostProcessor（处理 @Autowired）
    //   - CommonAnnotationBeanPostProcessor（处理 @PostConstruct/@PreDestroy/@Resource）
    //   - EventListenerMethodProcessor（处理 @EventListener）
    //   - DefaultEventListenerFactory（创建事件监听器适配器）
    // 这些基础设施 Bean 是后续一切功能的基础！
    this.reader = new AnnotatedBeanDefinitionReader(this);

    // 创建「类路径 Bean 定义扫描器」
    // 作用：扫描指定包路径下的 @Component 类
    // 注意：这个 scanner 是给用户手动调用 scan() 方法用的
    // @ComponentScan 注解的扫描是由 ConfigurationClassPostProcessor 内部创建的另一个 Scanner 完成的
    this.scanner = new ClassPathBeanDefinitionScanner(this);
}
```

### prepareBeanFactory() — 配置 BeanFactory 标准特性

> 文件：`AbstractApplicationContext.java`

```java
// === AbstractApplicationContext.java ===
// 为 BeanFactory 配置标准的上下文特性
protected void prepareBeanFactory(ConfigurableListableBeanFactory beanFactory) {

    // 设置类加载器：用于后续通过 BeanClassName 加载 Bean 的 Class 对象
    // 默认使用当前线程的上下文类加载器
    beanFactory.setBeanClassLoader(getClassLoader());

    // 设置 SpEL 表达式解析器
    // 让 @Value("#{systemProperties['user.name']}") 这种 SpEL 表达式能被解析
    // 注意区分：${...} 是属性占位符（由 PropertySourcesPlaceholderConfigurer 处理）
    //          #{...} 是 SpEL 表达式（由这个解析器处理）
    if (!shouldIgnoreSpel) {
        beanFactory.setBeanExpressionResolver(
            new StandardBeanExpressionResolver(beanFactory.getBeanClassLoader()));
    }

    // 注册属性编辑器注册器
    // 用于将字符串类型的属性值转换为目标类型
    // 例如：将 "classpath:config.xml" 字符串转换为 Resource 对象
    beanFactory.addPropertyEditorRegistrar(
        new ResourceEditorRegistrar(this, getEnvironment()));

    // 注册 ApplicationContextAwareProcessor（重要！）
    // 这是一个 BeanPostProcessor，在 Bean 初始化前执行
    // 它负责处理以下 Aware 接口的回调：
    //   EnvironmentAware → 注入 Environment
    //   ResourceLoaderAware → 注入 ResourceLoader
    //   ApplicationEventPublisherAware → 注入事件发布器
    //   MessageSourceAware → 注入国际化资源
    //   ApplicationContextAware → 注入 ApplicationContext
    //   ApplicationStartupAware → 注入 ApplicationStartup
    beanFactory.addBeanPostProcessor(new ApplicationContextAwareProcessor(this));

    // 忽略以下 Aware 接口的自动注入
    // 因为上面的 ApplicationContextAwareProcessor 已经统一处理了这些 Aware 回调
    // 如果不忽略，@Autowired 会尝试按类型注入，可能导致冲突
    beanFactory.ignoreDependencyInterface(EnvironmentAware.class);
    beanFactory.ignoreDependencyInterface(EmbeddedValueResolverAware.class);
    beanFactory.ignoreDependencyInterface(ResourceLoaderAware.class);
    beanFactory.ignoreDependencyInterface(ApplicationEventPublisherAware.class);
    beanFactory.ignoreDependencyInterface(MessageSourceAware.class);
    beanFactory.ignoreDependencyInterface(ApplicationContextAware.class);
    beanFactory.ignoreDependencyInterface(ApplicationStartupAware.class);

    // 注册可解析的依赖
    // 当有人 @Autowired BeanFactory 时，注入的就是这里注册的实例
    // 而不是去查找 BeanFactory 类型的 BeanDefinition
    beanFactory.registerResolvableDependency(BeanFactory.class, beanFactory);
    beanFactory.registerResolvableDependency(ResourceLoader.class, this);
    beanFactory.registerResolvableDependency(ApplicationEventPublisher.class, this);
    beanFactory.registerResolvableDependency(ApplicationContext.class, this);

    // 注册 ApplicationListenerDetector
    // 也是一个 BeanPostProcessor，在 Bean 初始化后检查它是否实现了 ApplicationListener
    // 如果是，自动注册到事件广播器中
    beanFactory.addBeanPostProcessor(new ApplicationListenerDetector(this));

    // 注册环境相关的单例 Bean（不需要 BeanDefinition，直接注册实例）
    // 这样你就可以 @Autowired Environment environment 来获取环境配置
    if (!beanFactory.containsLocalBean(ENVIRONMENT_BEAN_NAME)) {
        beanFactory.registerSingleton(ENVIRONMENT_BEAN_NAME, getEnvironment());
    }
    // 注册 JVM 系统属性（如 -Dkey=value 设置的参数）
    if (!beanFactory.containsLocalBean(SYSTEM_PROPERTIES_BEAN_NAME)) {
        beanFactory.registerSingleton(SYSTEM_PROPERTIES_BEAN_NAME,
            getEnvironment().getSystemProperties());
    }
    // 注册操作系统环境变量（如 PATH、JAVA_HOME 等）
    if (!beanFactory.containsLocalBean(SYSTEM_ENVIRONMENT_BEAN_NAME)) {
        beanFactory.registerSingleton(SYSTEM_ENVIRONMENT_BEAN_NAME,
            getEnvironment().getSystemEnvironment());
    }
}
```

### doGetBean() — Bean 获取总入口

```java
// === AbstractBeanFactory.java ===
// getBean("userService") 最终会调用这个方法
// 这是获取/创建 Bean 的总控方法
protected <T> T doGetBean(
        String name,              // Bean 名称（可能带 & 前缀或是别名）
        Class<T> requiredType,    // 期望的类型（可以为 null）
        Object[] args,            // 构造器参数（通常为 null）
        boolean typeCheckOnly)    // 是否仅做类型检查（不标记为已创建）
        throws BeansException {

    // 第 1 步：转换 Bean 名称
    // 处理两种特殊情况：
    //   a. 去掉 & 前缀：&myBean → myBean（& 前缀表示获取 FactoryBean 本身）
    //   b. 解析别名：如果 name 是别名，转换为真正的 beanName
    String beanName = transformedBeanName(name);
    Object beanInstance;

    // 第 2 步：尝试从缓存中获取单例 Bean
    // 这里会查三级缓存（一级 → 二级 → 三级），详见后面的 getSingleton() 详解
    // 如果之前已经创建过，直接从一级缓存返回
    // 如果正在创建中（循环依赖），从二级或三级缓存返回早期引用
    Object sharedInstance = getSingleton(beanName);

    if (sharedInstance != null && args == null) {
        // 缓存命中！但还需要做一个处理：
        // 如果缓存中的是 FactoryBean，而用户请求的不是 FactoryBean 本身（没有 & 前缀）
        // 则需要调用 FactoryBean.getObject() 获取实际产出对象
        // 例如：SqlSessionFactoryBean 缓存的是 FactoryBean 本身，
        //       但 getBean("sqlSessionFactory") 应该返回 SqlSessionFactory
        beanInstance = getObjectForBeanInstance(sharedInstance, name, beanName, null);
    }
    else {
        // 缓存未命中，需要创建 Bean

        // 第 3 步：检查 Prototype 作用域的循环依赖
        // Prototype 不缓存，无法解决循环依赖，直接报错
        // 通过 ThreadLocal 记录当前线程正在创建的 Prototype Bean
        if (isPrototypeCurrentlyInCreation(beanName)) {
            throw new BeanCurrentlyInCreationException(beanName);
        }

        // 第 4 步：检查父容器
        // 如果当前 BeanFactory 没有这个 BeanDefinition，但有父 BeanFactory
        // 就委托给父 BeanFactory 查找（类似 ClassLoader 的双亲委派）
        // 典型场景：Spring MVC 的子容器找不到 Bean，委托给父容器（Root WebApplicationContext）
        BeanFactory parentBeanFactory = getParentBeanFactory();
        if (parentBeanFactory != null && !containsBeanDefinition(beanName)) {
            // 转换回原始名称（加回 & 前缀，如果有的话）
            String nameToLookup = originalBeanName(name);
            // 委托给父 BeanFactory
            return parentBeanFactory.getBean(nameToLookup, requiredType);
        }

        // 第 5 步：标记 Bean 正在创建
        // 将 beanName 加入 alreadyCreated 集合
        // 同时清除该 Bean 的 MergedBeanDefinition 缓存（因为可能被 BFPP 修改过）
        if (!typeCheckOnly) {
            markBeanAsCreated(beanName);
        }

        try {
            // 第 6 步：获取合并后的 BeanDefinition
            // 如果 Bean 有 parent 属性（BeanDefinition 继承），需要合并父子定义
            // 合并后得到 RootBeanDefinition，包含所有配置信息
            // 合并后的结果会被缓存在 mergedBeanDefinitions Map 中
            RootBeanDefinition mbd = getMergedLocalBeanDefinition(beanName);
            // 检查 BeanDefinition 是否合法（不能是抽象的）
            checkMergedBeanDefinition(mbd, beanName, args);

            // 第 7 步：处理 @DependsOn 依赖
            // @DependsOn("dataSource") 表示当前 Bean 依赖 dataSource，必须先创建它
            // 注意：这不是 @Autowired 依赖，而是显式声明的创建顺序依赖
            String[] dependsOn = mbd.getDependsOn();
            if (dependsOn != null) {
                for (String dep : dependsOn) {
                    // 检查是否存在循环 @DependsOn（A depends-on B, B depends-on A）
                    if (isDependent(beanName, dep)) {
                        throw new BeanCreationException("Circular depends-on ...");
                    }
                    // 记录依赖关系（用于容器销毁时按逆序销毁）
                    registerDependentBean(dep, beanName);
                    // 递归创建被依赖的 Bean
                    getBean(dep);
                }
            }

            // 第 8 步：根据作用域创建 Bean
            if (mbd.isSingleton()) {
                // ===== 单例作用域 =====
                // 通过 getSingleton(beanName, ObjectFactory) 方法创建
                // 这个方法会：
                //   1. 加锁（synchronized）
                //   2. 再次检查一级缓存（双重检查）
                //   3. 标记 Bean 正在创建（加入 singletonsCurrentlyInCreation）
                //   4. 调用传入的 ObjectFactory（即下面的 lambda）创建 Bean
                //   5. 移除创建中标记
                //   6. 将创建好的 Bean 放入一级缓存
                sharedInstance = getSingleton(beanName, () -> {
                    // 这个 lambda 就是 ObjectFactory.getObject() 的实现
                    // 里面调用 createBean()，这才是真正创建 Bean 的方法
                    return createBean(beanName, mbd, args);
                });
                // 处理 FactoryBean（同上）
                beanInstance = getObjectForBeanInstance(sharedInstance, name, beanName, mbd);
            }
            else if (mbd.isPrototype()) {
                // ===== 原型作用域 =====
                // 每次都创建新实例，不缓存
                Object prototypeInstance = null;
                try {
                    // 标记 Prototype 正在创建（ThreadLocal，用于循环依赖检测）
                    beforePrototypeCreation(beanName);
                    // 创建 Bean
                    prototypeInstance = createBean(beanName, mbd, args);
                } finally {
                    // 移除创建中标记
                    afterPrototypeCreation(beanName);
                }
                beanInstance = getObjectForBeanInstance(prototypeInstance, name, beanName, mbd);
            }
            else {
                // ===== 其他作用域（request、session 等）=====
                String scopeName = mbd.getScope();
                // 从 scopes Map 中获取对应的 Scope 实现
                // 例如：RequestScope、SessionScope
                Scope scope = this.scopes.get(scopeName);
                // 委托给 Scope 管理 Bean 的生命周期
                Object scopedInstance = scope.get(beanName, () -> {
                    beforePrototypeCreation(beanName);
                    try {
                        return createBean(beanName, mbd, args);
                    } finally {
                        afterPrototypeCreation(beanName);
                    }
                });
                beanInstance = getObjectForBeanInstance(scopedInstance, name, beanName, mbd);
            }
        } catch (BeansException ex) {
            // 创建失败，从 alreadyCreated 集合移除
            beanCreation.tag("exception", ex.getClass().toString());
            cleanupAfterBeanCreationFailure(beanName);
            throw ex;
        }
    }

    // 第 9 步：类型检查和转换
    // 如果调用方指定了 requiredType，检查返回的 Bean 是否匹配
    // 如果不匹配，尝试通过 TypeConverter 转换
    return adaptBeanInstance(name, beanInstance, requiredType);
}
```

### doCreateBean() — Bean 实际创建

```java
// === AbstractAutowireCapableBeanFactory.java ===
// 这是 Bean 创建的核心方法，包含实例化、属性填充、初始化三大步骤
protected Object doCreateBean(String beanName, RootBeanDefinition mbd, Object[] args) throws BeanCreationException {

    // ========== 第一阶段：实例化 ==========

    // BeanWrapper 是对 Bean 实例的包装，提供属性设置的能力
    BeanWrapper instanceWrapper = null;

    // 如果是单例，先尝试从缓存获取（可能之前 factoryBeanInstanceCache 中有未完成的）
    if (mbd.isSingleton()) {
        instanceWrapper = this.factoryBeanInstanceCache.remove(beanName);
    }

    if (instanceWrapper == null) {
        // 创建 Bean 实例（只是实例化，属性还没填充）
        // 内部逻辑：
        //   1. 如果有 @Bean 方法 → 通过工厂方法（反射调用 @Bean 方法）创建
        //   2. 如果有 @Autowired 构造器 → 使用该构造器创建
        //   3. 如果只有一个有参构造器 → 使用该构造器
        //   4. 否则使用默认无参构造器
        // 使用 CGLIB 或反射来调用构造器
        instanceWrapper = createBeanInstance(beanName, mbd, args);
    }

    // 获取原始的 Bean 实例（还没有被代理的原始对象）
    Object bean = instanceWrapper.getWrappedInstance();
    // 获取 Bean 的实际类型
    Class<?> beanType = instanceWrapper.getWrappedClass();
    if (beanType != NullBean.class) {
        mbd.resolvedTargetType = beanType;
    }

    // ========== 调用 MergedBeanDefinitionPostProcessor ==========
    // 在属性填充之前，让后置处理器有机会修改 BeanDefinition
    // 重点：AutowiredAnnotationBeanPostProcessor 在这里扫描 @Autowired 注解
    //       收集所有需要注入的字段和方法，缓存到 InjectionMetadata 中
    //       这样在后面 populateBean() 时就知道要注入哪些依赖
    synchronized (mbd.postProcessingLock) {
        if (!mbd.postProcessed) {
            applyMergedBeanDefinitionPostProcessors(mbd, beanType, beanName);
            mbd.markAsPostProcessed();
        }
    }

    // ========== 第二阶段：提前暴露（解决循环依赖）==========

    // 判断是否需要提前暴露引用
    // 条件：单例 && 允许循环引用 && 当前 Bean 正在创建中
    boolean earlySingletonExposure = (mbd.isSingleton()            // 必须是单例
        && this.allowCircularReferences                             // 允许循环引用（默认 true）
        && isSingletonCurrentlyInCreation(beanName));               // 正在创建中

    if (earlySingletonExposure) {
        // 将 Bean 的 ObjectFactory 放入三级缓存！
        // 这是解决循环依赖的关键！
        //
        // 当另一个 Bean 依赖当前 Bean 时，会从三级缓存获取 ObjectFactory
        // 调用 ObjectFactory.getObject() 时，会执行 getEarlyBeanReference()
        // getEarlyBeanReference() 会调用所有 SmartInstantiationAwareBeanPostProcessor
        //   如果有 AOP，AbstractAutoProxyCreator 会在这里提前创建代理对象
        //   如果没有 AOP，直接返回原始 Bean 实例
        addSingletonFactory(beanName, () -> getEarlyBeanReference(beanName, mbd, bean));
    }

    // ========== 第三阶段：属性填充 ==========

    Object exposedObject = bean;  // 最终暴露的对象（可能是原始对象，也可能是代理对象）
    try {
        // 填充 Bean 属性（依赖注入在这里发生！）
        // 内部调用 InstantiationAwareBeanPostProcessor.postProcessProperties()
        // 重点：AutowiredAnnotationBeanPostProcessor.postProcessProperties()
        //   遍历之前收集的 InjectionMetadata（@Autowired 字段和方法）
        //   对每个注入点调用 beanFactory.resolveDependency() 解析依赖
        //   然后通过反射 field.set(bean, value) 注入值
        //
        // 如果注入的依赖还没创建，会递归调用 getBean() 创建它
        // 如果出现循环依赖，就会走到三级缓存获取早期引用
        populateBean(beanName, mbd, instanceWrapper);

        // ========== 第四阶段：初始化 ==========
        // 执行各种初始化回调，顺序如下：
        //   1. invokeAwareMethods()：BeanNameAware、BeanFactoryAware 回调
        //   2. BeanPostProcessor.postProcessBeforeInitialization()
        //      → ApplicationContextAwareProcessor：ApplicationContextAware 等回调
        //      → CommonAnnotationBeanPostProcessor：@PostConstruct 方法调用
        //   3. invokeInitMethods()
        //      → InitializingBean.afterPropertiesSet()
        //      → 自定义 init-method
        //   4. BeanPostProcessor.postProcessAfterInitialization()
        //      → AbstractAutoProxyCreator：如果需要 AOP，在这里创建代理对象！
        //        返回的 exposedObject 就变成了代理对象，而不是原始 Bean
        exposedObject = initializeBean(beanName, bean, mbd);

    } catch (Throwable ex) {
        // ... 异常处理
    }

    // ========== 第五阶段：循环依赖校验 ==========

    if (earlySingletonExposure) {
        // 从缓存获取最终的单例对象（不允许从三级缓存获取，只查一级和二级）
        Object earlySingletonReference = getSingleton(beanName, false);
        if (earlySingletonReference != null) {
            // 如果初始化后的对象和原始对象相同（没有被代理替换）
            if (exposedObject == bean) {
                // 使用早期引用作为最终暴露对象
                // 这样其他已经注入了早期引用的 Bean 持有的引用是正确的
                exposedObject = earlySingletonReference;
            }
            // 如果不相同（被代理了），检查是否有其他 Bean 已经注入了原始引用
            // 如果有，说明存在问题：其他 Bean 持有的是原始对象，而不是代理对象
            // 这种情况在 allowRawInjectionDespiteWrapping=false 时会报错
        }
    }

    // ========== 第六阶段：注册销毁回调 ==========

    try {
        // 如果 Bean 实现了 DisposableBean 或有 @PreDestroy 或有 destroy-method
        // 就注册一个 DisposableBeanAdapter，容器关闭时调用
        registerDisposableBeanIfNecessary(beanName, bean, mbd);
    } catch (BeanDefinitionValidationException ex) {
        throw new BeanCreationException(...);
    }

    // 返回最终的 Bean 实例（可能是原始对象，也可能是代理对象）
    return exposedObject;
}
```

## 三、三级缓存 — getSingleton()

> 文件：`DefaultSingletonBeanRegistry.java`
> 断点位置：`org.springframework.beans.factory.support.DefaultSingletonBeanRegistry#getSingleton(java.lang.String, boolean)`

```java
// === DefaultSingletonBeanRegistry.java ===
// 这是解决循环依赖的核心方法！面试高频考点

// 三级缓存数据结构：
// 一级缓存 singletonObjects：      Map<String, Object>          完整的 Bean 实例
// 二级缓存 earlySingletonObjects：  Map<String, Object>          提前暴露的 Bean（可能是代理）
// 三级缓存 singletonFactories：     Map<String, ObjectFactory>   Bean 的 ObjectFactory 回调

// 查询缓存的方法
protected Object getSingleton(String beanName, boolean allowEarlyReference) {

    // 第 1 步：查一级缓存（存放完全初始化好的 Bean）
    // ConcurrentHashMap，不需要加锁就能读取
    // 绝大多数情况下，Bean 都在一级缓存中，直接命中返回
    Object singletonObject = this.singletonObjects.get(beanName);

    // 如果一级缓存没有，并且这个 Bean 正在创建中（说明可能存在循环依赖）
    if (singletonObject == null && isSingletonCurrentlyInCreation(beanName)) {

        // 第 2 步：查二级缓存（存放提前暴露的 Bean 实例）
        // 二级缓存中的 Bean 可能已经被 AOP 代理包装过了
        singletonObject = this.earlySingletonObjects.get(beanName);

        // 如果二级缓存也没有，并且允许获取早期引用
        if (singletonObject == null && allowEarlyReference) {

            // 需要加锁！因为接下来要操作三级缓存并升级到二级缓存
            // 必须保证这个过程是原子的
            synchronized (this.singletonObjects) {

                // 双重检查锁定（DCL）
                // 再次检查一级缓存（可能在等锁期间被其他线程放入了）
                singletonObject = this.singletonObjects.get(beanName);

                if (singletonObject == null) {
                    // 再次检查二级缓存
                    singletonObject = this.earlySingletonObjects.get(beanName);

                    if (singletonObject == null) {
                        // 第 3 步：查三级缓存（存放 ObjectFactory 回调）
                        ObjectFactory<?> singletonFactory = this.singletonFactories.get(beanName);

                        if (singletonFactory != null) {
                            // 找到了！调用 ObjectFactory.getObject() 获取早期引用
                            // 这个 ObjectFactory 是在 doCreateBean() 中通过
                            // addSingletonFactory() 放入的
                            //
                            // getObject() 内部调用 getEarlyBeanReference(beanName, mbd, bean)
                            // getEarlyBeanReference() 会遍历所有 SmartInstantiationAwareBeanPostProcessor
                            //   如果有 AOP 代理需求（AbstractAutoProxyCreator）：
                            //     → 提前创建代理对象，返回代理
                            //   如果没有 AOP：
                            //     → 直接返回原始 Bean 实例
                            singletonObject = singletonFactory.getObject();

                            // 升级：从三级缓存移到二级缓存
                            // 这样下次再获取就直接从二级缓存拿，不会重复创建代理
                            this.earlySingletonObjects.put(beanName, singletonObject);

                            // 移除三级缓存（已经用过了）
                            this.singletonFactories.remove(beanName);
                        }
                    }
                }
            }
        }
    }
    return singletonObject;
}

// 创建新单例的方法（注意这是另一个重载方法，参数是 ObjectFactory）
public Object getSingleton(String beanName, ObjectFactory<?> singletonFactory) {
    // 整个方法在 synchronized(this.singletonObjects) 内执行

    synchronized (this.singletonObjects) {
        // 双重检查：再次从一级缓存查，可能已经被创建了
        Object singletonObject = this.singletonObjects.get(beanName);

        if (singletonObject == null) {
            // 标记为正在创建：将 beanName 加入 singletonsCurrentlyInCreation Set
            // 后续 getSingleton(beanName, true) 时会通过
            // isSingletonCurrentlyInCreation() 检查这个标记
            beforeSingletonCreation(beanName);

            boolean newSingleton = false;
            try {
                // 调用传入的 ObjectFactory 创建 Bean
                // 对应 doGetBean() 中的 lambda：() -> createBean(beanName, mbd, args)
                // 这里面会经历完整的 Bean 创建流程：
                //   createBean() → doCreateBean() → 实例化 → 属性填充 → 初始化
                singletonObject = singletonFactory.getObject();
                newSingleton = true;
            } catch (IllegalStateException ex) {
                // ... 异常处理
            } finally {
                // 移除正在创建的标记
                afterSingletonCreation(beanName);
            }

            if (newSingleton) {
                // 添加到一级缓存，同时清除二三级缓存
                // singletonObjects.put(beanName, singletonObject);   ← 放入一级
                // singletonFactories.remove(beanName);                ← 移除三级
                // earlySingletonObjects.remove(beanName);             ← 移除二级
                // registeredSingletons.add(beanName);                 ← 记录已注册
                addSingleton(beanName, singletonObject);
            }
        }
        return singletonObject;
    }
}
```

## 四、依赖注入 — doResolveDependency()

> 文件：`DefaultListableBeanFactory.java`
> 断点位置：`org.springframework.beans.factory.support.DefaultListableBeanFactory#doResolveDependency`

```java
// === DefaultListableBeanFactory.java ===
// 当 @Autowired 需要注入一个依赖时，最终调用到这个方法
// 它负责"根据类型找到匹配的 Bean 并返回"
public Object doResolveDependency(
        DependencyDescriptor descriptor,    // 描述注入点信息（字段/方法参数的类型、注解等）
        String beanName,                    // 当前正在创建的 Bean 名称（注入到谁）
        Set<String> autowiredBeanNames,     // 输出参数：记录实际注入了哪些 Bean 的名称
        TypeConverter typeConverter)         // 类型转换器
        throws BeansException {

    // 第 1 步：处理 @Value 注解
    // getAutowireCandidateResolver() 返回的是 ContextAnnotationAutowireCandidateResolver
    // getSuggestedValue() 会检查字段/参数上是否有 @Value 注解
    // 如果有，返回注解的 value 值（如 "${server.port}" 或 "#{1+1}"）
    Object value = getAutowireCandidateResolver().getSuggestedValue(descriptor);

    if (value != null) {
        // 有 @Value 注解

        if (value instanceof String strValue) {
            // 解析 ${...} 占位符
            // 例如 "${server.port:8080}" → "8080"（从 application.properties 读取）
            // 由 PropertySourcesPlaceholderConfigurer 注册的 StringValueResolver 处理
            String resolvedValue = resolveEmbeddedValue(strValue);

            // 解析 #{...} SpEL 表达式
            // 例如 "#{T(java.lang.Math).PI}" → 3.14159...
            // 由 StandardBeanExpressionResolver 处理
            BeanDefinition bd = (beanName != null && containsBean(beanName))
                ? getMergedBeanDefinition(beanName) : null;
            value = evaluateBeanDefinitionString(resolvedValue, bd);
        }

        // 类型转换：将字符串 "8080" 转换为目标类型 int/Integer
        TypeConverter converter = (typeConverter != null ? typeConverter : getTypeConverter());
        return converter.convertIfNecessary(value, descriptor.getDependencyType(),
            descriptor.getTypeDescriptor());
    }

    // 第 2 步：处理集合类型注入
    // @Autowired List<MyService> services; → 注入所有 MyService 类型的 Bean
    // @Autowired Map<String, MyService> serviceMap; → key=beanName, value=bean
    // @Autowired MyService[] services; → 注入所有匹配的 Bean 到数组
    Object multipleBeans = resolveMultipleBeans(descriptor, beanName, autowiredBeanNames, typeConverter);
    if (multipleBeans != null) {
        return multipleBeans;
    }

    // 第 3 步：按类型查找候选 Bean
    // 从 BeanFactory 中查找所有类型匹配的 Bean
    // 返回 Map<String, Object>，key=beanName, value=bean实例或Class
    // （如果 Bean 还没创建，value 是 Class 对象而不是实例）
    Map<String, Object> matchingBeans = findAutowireCandidates(beanName, type, descriptor);

    // 没有找到任何匹配的 Bean
    if (matchingBeans.isEmpty()) {
        if (isRequired(descriptor)) {
            // required=true（默认）→ 抛出 NoSuchBeanDefinitionException
            // 这就是你经常看到的 "No qualifying bean of type 'xxx' available" 错误
            raiseNoMatchingBeanFound(type, descriptor.getResolvableType(), descriptor);
        }
        // required=false → 返回 null
        return null;
    }

    String autowiredBeanName;
    Object instanceCandidate;

    // 第 4 步：如果有多个匹配的 Bean，需要决定用哪个
    if (matchingBeans.size() > 1) {
        // 按优先级筛选，规则顺序如下：
        //   规则 1：@Primary 标记的 Bean 优先
        //   规则 2：@Priority 值最小的优先（jakarta.annotation.Priority）
        //   规则 3：字段名/参数名与 beanName 匹配的优先
        //           例如 @Autowired private DataSource mysqlDataSource;
        //           会优先匹配名为 "mysqlDataSource" 的 Bean
        autowiredBeanName = determineAutowireCandidate(matchingBeans, descriptor);

        if (autowiredBeanName == null) {
            if (isRequired(descriptor) || !indicatesMultipleBeans(type)) {
                // 无法确定唯一候选 → 抛出 NoUniqueBeanDefinitionException
                // "expected single matching bean but found 2: beanA, beanB"
                return descriptor.resolveNotUnique(descriptor.getResolvableType(), matchingBeans);
            }
            return null;
        }
        instanceCandidate = matchingBeans.get(autowiredBeanName);
    } else {
        // 只有一个匹配，直接使用
        Map.Entry<String, Object> entry = matchingBeans.entrySet().iterator().next();
        autowiredBeanName = entry.getKey();
        instanceCandidate = entry.getValue();
    }

    // 记录注入了哪个 Bean（用于依赖关系跟踪）
    if (autowiredBeanNames != null) {
        autowiredBeanNames.add(autowiredBeanName);
    }

    // 第 5 步：如果候选是 Class 对象（还没实例化），通过 getBean() 创建实例
    // 这就是"懒加载"的效果：依赖的 Bean 在被需要时才创建
    if (instanceCandidate instanceof Class) {
        instanceCandidate = descriptor.resolveCandidate(autowiredBeanName, type, this);
        // resolveCandidate 内部就是调用 beanFactory.getBean(autowiredBeanName)
    }

    // 返回解析到的 Bean 实例
    return instanceCandidate;
}
```

## 五、AOP 代理创建 — wrapIfNecessary()

> 文件：`AbstractAutoProxyCreator.java`
> 断点位置：`org.springframework.aop.framework.autoproxy.AbstractAutoProxyCreator#wrapIfNecessary`

```java
// === AbstractAutoProxyCreator.java ===
// 这个方法在每个 Bean 初始化完成后被调用（postProcessAfterInitialization）
// 它决定是否要为这个 Bean 创建 AOP 代理

// 入口方法
@Override
public Object postProcessAfterInitialization(Object bean, String beanName) {
    if (bean != null) {
        // 生成缓存 key（通常就是 beanName）
        Object cacheKey = getCacheKey(bean.getClass(), beanName);

        // 检查是否已经在循环依赖时提前创建了代理
        // earlyProxyReferences 记录了在三级缓存 getEarlyBeanReference() 中
        // 已经提前创建过代理的 Bean
        // 如果提前创建过，就不需要再创建了（避免重复代理）
        if (this.earlyProxyReferences.remove(cacheKey) != bean) {
            // 还没创建过代理，尝试包装
            return wrapIfNecessary(bean, beanName, cacheKey);
        }
    }
    return bean;
}

// 核心方法：判断并创建代理
protected Object wrapIfNecessary(Object bean, String beanName, Object cacheKey) {

    // 已经通过 TargetSourceCreator 处理过的 Bean，跳过
    if (StringUtils.hasLength(beanName) && this.targetSourcedBeans.contains(beanName)) {
        return bean;
    }

    // 之前已经判断过不需要代理的 Bean，跳过
    // advisedBeans 是一个缓存 Map<Object, Boolean>
    if (Boolean.FALSE.equals(this.advisedBeans.get(cacheKey))) {
        return bean;
    }

    // 基础设施类不需要代理（Advice、Pointcut、Advisor、AopInfrastructureBean）
    // 因为这些类本身就是 AOP 框架的一部分，给它们创建代理没有意义
    // 同时检查 bean 名称是否以 ".ORIGINAL" 结尾（Spring 内部标记）
    if (isInfrastructureClass(bean.getClass()) || shouldSkip(bean.getClass(), beanName)) {
        // 标记为不需要代理，下次直接跳过
        this.advisedBeans.put(cacheKey, Boolean.FALSE);
        return bean;
    }

    // ===== 关键步骤：查找适用于当前 Bean 的增强器（Advisor） =====
    // 这一步会：
    //   1. 获取所有候选 Advisor（从容器中找，包括解析 @Aspect 类）
    //   2. 过滤出能应用到当前 Bean 的 Advisor（通过 Pointcut 匹配）
    //      Pointcut 匹配会检查：
    //        a. ClassFilter.matches(beanClass) — 类级别匹配
    //        b. MethodMatcher.matches(method, beanClass) — 方法级别匹配
    //      例如 @Around("execution(* com.example.service.*.*(..))")
    //        会匹配 com.example.service 包下所有类的所有方法
    Object[] specificInterceptors = getAdvicesAndAdvisorsForBean(
        bean.getClass(), beanName, null);

    // DO_NOT_PROXY 是一个特殊标记，表示不需要代理
    if (specificInterceptors != DO_NOT_PROXY) {
        // 有匹配的增强器！需要创建代理

        // 标记为已代理
        this.advisedBeans.put(cacheKey, Boolean.TRUE);

        // ===== 创建代理对象 =====
        // createProxy() 内部：
        //   1. 创建 ProxyFactory
        //   2. 决定使用 JDK 动态代理还是 CGLIB：
        //      - 有接口且没有强制 proxyTargetClass=true → JDK 代理
        //      - 没有接口或 proxyTargetClass=true → CGLIB 代理
        //      - Spring Boot 2.x+ 默认 proxyTargetClass=true → 都用 CGLIB
        //   3. 将所有 Advisor 添加到 ProxyFactory
        //   4. 调用 proxyFactory.getProxy() 生成代理对象
        Object proxy = createProxy(
            bean.getClass(),                    // 目标类
            beanName,                           // Bean 名称
            specificInterceptors,               // 匹配的增强器数组
            new SingletonTargetSource(bean));    // 目标源（包装原始 Bean）

        // 缓存代理类型
        this.proxyTypes.put(cacheKey, proxy.getClass());

        // 返回代理对象！
        // 从此以后，容器中存的就是这个代理对象
        // 其他 Bean @Autowired 注入的也是代理对象
        return proxy;
    }

    // 没有匹配的增强器，不需要代理
    this.advisedBeans.put(cacheKey, Boolean.FALSE);
    return bean;
}
```

## 六、拦截器链执行 — proceed()

> 文件：`ReflectiveMethodInvocation.java`
> 断点位置：`org.springframework.aop.framework.ReflectiveMethodInvocation#proceed`

```java
// === ReflectiveMethodInvocation.java ===
// 当调用代理对象的方法时，会进入拦截器链的执行
// 这是一个递归结构：每个拦截器调用 proceed() 触发下一个拦截器

// 假设有 3 个拦截器：[Around, Before, AfterReturning]
// 执行流程：
//   proceed() → Around.invoke(this)
//     → proceed() → Before.invoke(this)  // Before 先执行前置逻辑
//       → proceed() → 调用目标方法       // 所有拦截器执行完，调用真正的业务方法
//       ← 返回结果
//     ← Before 返回
//   ← Around 执行后置逻辑，返回

// currentInterceptorIndex 从 -1 开始，每次 proceed() 加 1
@Override
public Object proceed() throws Throwable {

    // 判断是否所有拦截器都执行完了
    // interceptorsAndDynamicMethodMatchers 是拦截器列表
    // currentInterceptorIndex 从 -1 开始，每次 +1
    // 当 index 等于列表最后一个元素的下标时，说明所有拦截器都执行过了
    if (this.currentInterceptorIndex == this.interceptorsAndDynamicMethodMatchers.size() - 1) {
        // 所有拦截器执行完毕！调用目标方法（反射调用原始 Bean 的方法）
        // invokeJoinpoint() 内部就是 method.invoke(target, args)
        return invokeJoinpoint();
    }

    // 获取下一个拦截器（index 先 +1 再获取）
    Object interceptorOrInterceptionAdvice =
        this.interceptorsAndDynamicMethodMatchers.get(++this.currentInterceptorIndex);

    // 检查是否是动态匹配（需要运行时根据参数判断是否匹配）
    if (interceptorOrInterceptionAdvice instanceof InterceptorAndDynamicMethodMatcher dm) {
        // 动态匹配器：运行时检查方法参数是否符合 Pointcut 条件
        Class<?> targetClass = (this.targetClass != null
            ? this.targetClass : this.method.getDeclaringClass());

        if (dm.matcher().matches(this.method, targetClass, this.arguments)) {
            // 参数匹配，执行拦截器
            // 拦截器内部会调用 invocation.proceed()（也就是 this.proceed()）
            // 从而触发下一个拦截器，形成递归
            return dm.interceptor().invoke(this);
        } else {
            // 参数不匹配，跳过当前拦截器，执行下一个
            return proceed();
        }
    } else {
        // 静态拦截器（大多数情况）：直接执行
        // 拦截器内部的典型结构：
        //
        // @Before → MethodBeforeAdviceInterceptor：
        //   advice.before(method, args, target);  // 先执行前置逻辑
        //   return mi.proceed();                  // 然后继续链
        //
        // @After → AspectJAfterAdvice：
        //   try { return mi.proceed(); }          // 先继续链
        //   finally { invokeAdviceMethod(); }     // 无论如何都执行后置逻辑
        //
        // @Around → 用户自定义的 MethodInterceptor：
        //   // 前置逻辑
        //   Object result = pjp.proceed();        // 用户决定何时继续链
        //   // 后置逻辑
        //   return result;
        return ((MethodInterceptor) interceptorOrInterceptionAdvice).invoke(this);
    }
}
```

## 七、事务管理 — invokeWithinTransaction()

> 文件：`TransactionAspectSupport.java`
> 断点位置：`org.springframework.transaction.interceptor.TransactionAspectSupport#invokeWithinTransaction`

```java
// === TransactionAspectSupport.java ===
// @Transactional 注解通过 AOP 拦截，最终调用到这个方法
// TransactionInterceptor 继承了 TransactionAspectSupport
// TransactionInterceptor.invoke() → invokeWithinTransaction()

protected Object invokeWithinTransaction(
        Method method,                  // 被 @Transactional 标注的方法
        Class<?> targetClass,           // 目标类
        InvocationCallback invocation)  // 执行目标方法的回调
        throws Throwable {

    // 第 1 步：获取事务属性源
    // TransactionAttributeSource 负责解析 @Transactional 注解
    TransactionAttributeSource tas = getTransactionAttributeSource();

    // 从方法和类上解析 @Transactional 注解的属性
    // 返回 TransactionAttribute，包含：
    //   propagation: 传播行为（REQUIRED / REQUIRES_NEW 等）
    //   isolation: 隔离级别
    //   timeout: 超时时间
    //   readOnly: 是否只读
    //   rollbackFor: 哪些异常回滚
    //   noRollbackFor: 哪些异常不回滚
    // 如果方法没有 @Transactional 注解，返回 null
    final TransactionAttribute txAttr = (tas != null
        ? tas.getTransactionAttribute(method, targetClass) : null);

    // 第 2 步：获取事务管理器
    // 确定使用哪个 PlatformTransactionManager
    // 查找顺序：
    //   1. @Transactional(transactionManager = "myTxManager") 指定的
    //   2. 容器中唯一的 PlatformTransactionManager
    //   3. 名为 "transactionManager" 的 Bean
    TransactionManager tm = determineTransactionManager(txAttr);
    PlatformTransactionManager ptm = asPlatformTransactionManager(tm);

    // 第 3 步：生成方法标识（用于日志和调试）
    // 格式："com.example.UserService.createUser"
    final String joinpointIdentification = methodIdentification(method, targetClass, txAttr);

    // 第 4 步：开启事务
    // 内部调用 transactionManager.getTransaction(txAttr)
    // 根据传播行为决定：
    //   - 创建新事务
    //   - 加入已有事务
    //   - 挂起已有事务
    //   - 以非事务方式执行
    // 返回 TransactionInfo，包含 TransactionStatus 和 TransactionManager
    // TransactionInfo 会绑定到当前线程的 ThreadLocal（链表结构，支持嵌套事务）
    TransactionInfo txInfo = createTransactionIfNecessary(ptm, txAttr, joinpointIdentification);

    Object retVal;
    try {
        // 第 5 步：执行目标方法
        // invocation.proceedWithInvocation() 就是调用真正的业务代码
        // 例如执行 userService.createUser() 的方法体
        // 方法体内的 SQL 操作会使用事务管理器绑定到 ThreadLocal 中的数据库连接
        // 这就是为什么同一个事务中的多个 SQL 共享同一个 Connection
        retVal = invocation.proceedWithInvocation();
    }
    catch (Throwable ex) {
        // 第 6 步：异常处理
        // 判断是否需要回滚：
        //   默认规则：RuntimeException 和 Error → 回滚
        //            受检异常（checked exception） → 不回滚（提交！）
        //   自定义规则：@Transactional(rollbackFor = Exception.class) → 所有异常都回滚
        //
        // 如果需要回滚：
        //   txInfo.getTransactionManager().rollback(txInfo.getTransactionStatus())
        //   → DataSourceTransactionManager.doRollback()
        //   → connection.rollback()
        //
        // 如果不需要回滚（受检异常且没有配置 rollbackFor）：
        //   txInfo.getTransactionManager().commit(txInfo.getTransactionStatus())
        //   → 即使抛了异常，事务也会提交！这是很常见的坑！
        completeTransactionAfterThrowing(txInfo, ex);

        // 重新抛出异常（事务框架不吞异常）
        throw ex;
    }
    finally {
        // 第 7 步：清理事务信息
        // 从 ThreadLocal 中移除当前 TransactionInfo
        // 恢复外层事务的 TransactionInfo（如果有嵌套事务的话）
        cleanupTransactionInfo(txInfo);
    }

    // 第 8 步：正常返回 → 提交事务
    // txInfo.getTransactionManager().commit(txInfo.getTransactionStatus())
    // → 触发 TransactionSynchronization 回调（beforeCommit / afterCommit）
    // → DataSourceTransactionManager.doCommit()
    // → connection.commit()
    // → 释放连接回连接池
    //
    // 注意：如果当前事务是 "加入" 到外层事务的（REQUIRED 传播行为）
    //       这里不会真正 commit，而是等外层事务 commit 时一起提交
    commitTransactionAfterReturning(txInfo);

    return retVal;
}
```

## 八、事务传播 — getTransaction()

> 文件：`AbstractPlatformTransactionManager.java`
> 断点位置：`org.springframework.transaction.support.AbstractPlatformTransactionManager#getTransaction`

```java
// === AbstractPlatformTransactionManager.java ===
// 事务传播行为的核心逻辑就在这个方法里
// 七种传播行为的判断逻辑都在这里

@Override
public final TransactionStatus getTransaction(TransactionDefinition definition) throws TransactionException {

    TransactionDefinition def = (definition != null ? definition : TransactionDefinition.withDefaults());

    // 第 1 步：获取当前线程的事务对象
    // 对于 DataSourceTransactionManager：
    //   从 TransactionSynchronizationManager 的 ThreadLocal 中获取当前线程绑定的 ConnectionHolder
    //   如果有 → 说明当前线程已经有活跃的数据库事务
    //   如果没有 → 说明当前线程没有事务
    Object transaction = doGetTransaction();

    // 第 2 步：检查当前是否已经存在事务
    // 判断 ConnectionHolder 是否不为 null，且 transactionActive=true
    if (isExistingTransaction(transaction)) {
        // ===== 已有事务的情况 =====
        // 根据传播行为决定如何处理（详见 handleExistingTransaction）
        return handleExistingTransaction(def, transaction, debugEnabled);
    }

    // ===== 以下是当前没有事务的情况 =====

    // 超时检查：timeout 必须 > 0 或等于默认值
    if (def.getTimeout() < TransactionDefinition.TIMEOUT_DEFAULT) {
        throw new InvalidTimeoutException("Invalid transaction timeout", def.getTimeout());
    }

    // MANDATORY：强制要求调用方已经有事务
    // 如果当前没有事务 → 直接报错
    // 使用场景：某些方法必须在事务中调用，如 "扣库存" 必须在 "下单" 的事务中
    if (def.getPropagationBehavior() == TransactionDefinition.PROPAGATION_MANDATORY) {
        throw new IllegalTransactionStateException(
            "No existing transaction found for transaction marked with propagation 'mandatory'");
    }

    // REQUIRED / REQUIRES_NEW / NESTED：需要创建新事务
    else if (def.getPropagationBehavior() == TransactionDefinition.PROPAGATION_REQUIRED ||
             def.getPropagationBehavior() == TransactionDefinition.PROPAGATION_REQUIRES_NEW ||
             def.getPropagationBehavior() == TransactionDefinition.PROPAGATION_NESTED) {

        // 挂起当前"空"事务（如果有事务同步在进行中）
        SuspendedResourcesHolder suspendedResources = suspend(null);

        try {
            // 开始新事务
            // startTransaction() 内部调用 doBegin()
            // DataSourceTransactionManager.doBegin() 会：
            //   1. 从 DataSource 获取新的 Connection
            //   2. connection.setAutoCommit(false)  ← 这就是开启事务！
            //   3. 设置隔离级别（如果指定了的话）
            //   4. 设置只读标志
            //   5. 将 Connection 绑定到当前线程的 ThreadLocal
            //      TransactionSynchronizationManager.bindResource(dataSource, connectionHolder)
            //   6. 这样后续同一线程的 SQL 操作都会使用这个 Connection
            return startTransaction(def, transaction, debugEnabled, suspendedResources);
        } catch (RuntimeException | Error ex) {
            // 开始事务失败，恢复之前挂起的资源
            resume(null, suspendedResources);
            throw ex;
        }
    }

    // SUPPORTS / NOT_SUPPORTED / NEVER：不创建事务
    else {
        // 以非事务方式执行
        // 创建一个空的 TransactionStatus（newTransaction=false）
        // SQL 操作会使用自动提交模式（每条 SQL 独立提交）
        boolean newSynchronization = (getTransactionSynchronization() == SYNCHRONIZATION_ALWAYS);
        return prepareTransactionStatus(def, null, true, newSynchronization, debugEnabled, null);
    }
}

// 已有事务时的传播行为处理
private TransactionStatus handleExistingTransaction(
        TransactionDefinition definition, Object transaction, boolean debugEnabled)
        throws TransactionException {

    // NEVER：不允许在事务中执行
    // 当前已经有事务了，但是方法标注了 NEVER → 报错
    if (definition.getPropagationBehavior() == TransactionDefinition.PROPAGATION_NEVER) {
        throw new IllegalTransactionStateException(
            "Existing transaction found for transaction marked with propagation 'never'");
    }

    // NOT_SUPPORTED：挂起当前事务，以非事务方式执行
    // 使用场景：某些操作不需要事务，如发送通知
    if (definition.getPropagationBehavior() == TransactionDefinition.PROPAGATION_NOT_SUPPORTED) {
        // 挂起当前事务：
        //   1. 从 ThreadLocal 解绑当前 ConnectionHolder
        //   2. 保存到 SuspendedResourcesHolder（方法执行完后恢复）
        Object suspendedResources = suspend(transaction);
        // 以非事务方式执行（autoCommit=true）
        boolean newSynchronization = (getTransactionSynchronization() == SYNCHRONIZATION_ALWAYS);
        return prepareTransactionStatus(
            definition, null, false, newSynchronization, debugEnabled, suspendedResources);
    }

    // REQUIRES_NEW：挂起当前事务，创建全新的独立事务
    // 使用场景：审计日志（即使业务回滚，日志也要保留）
    if (definition.getPropagationBehavior() == TransactionDefinition.PROPAGATION_REQUIRES_NEW) {
        // 挂起当前事务（同上）
        SuspendedResourcesHolder suspendedResources = suspend(transaction);
        try {
            // 创建全新的事务（获取新的 Connection，setAutoCommit(false)）
            // 这个新事务和外层事务完全独立：
            //   内部回滚 → 外部不受影响
            //   外部回滚 → 内部已提交的也不受影响
            return startTransaction(
                definition, transaction, debugEnabled, suspendedResources);
        } catch (RuntimeException | Error beginEx) {
            // 新事务创建失败，恢复之前挂起的事务
            resumeAfterBeginException(transaction, suspendedResources, beginEx);
            throw beginEx;
        }
    }

    // NESTED：嵌套事务，使用 Savepoint 实现
    // 使用场景：批量操作中单条失败不影响其他（回滚到 Savepoint）
    if (definition.getPropagationBehavior() == TransactionDefinition.PROPAGATION_NESTED) {
        if (!isNestedTransactionAllowed()) {
            throw new NestedTransactionNotSupportedException(...);
        }
        if (useSavepointForNestedTransaction()) {
            // 使用 JDBC Savepoint
            // 和外层事务共用同一个 Connection
            DefaultTransactionStatus status = prepareTransactionStatus(
                definition, transaction, false, false, debugEnabled, null);
            // 创建 Savepoint
            // connection.setSavepoint("SAVEPOINT_1")
            // 如果内部方法抛异常，回滚到这个 Savepoint
            // 外层事务不受影响，可以继续执行
            status.createAndHoldSavepoint();
            return status;
        } else {
            // 不支持 Savepoint（如 JTA），降级为创建新事务
            return startTransaction(definition, transaction, debugEnabled, null);
        }
    }

    // REQUIRED / SUPPORTS / MANDATORY：加入当前事务
    // 和外层事务共用同一个 Connection
    // 内部方法如果抛异常，整个事务都会回滚（因为是同一个事务）
    // 这是最常用的情况！
    if (isValidateExistingTransaction()) {
        // 验证事务属性是否兼容（如隔离级别是否一致）
        // 如果不一致，可能抛出异常
    }
    return prepareTransactionStatus(definition, transaction, false, newSynchronization, debugEnabled, null);
}
```

## 九、MVC 请求分发 — doDispatch()

> 文件：`DispatcherServlet.java`
> 断点位置：`org.springframework.web.servlet.DispatcherServlet#doDispatch`

```java
// === DispatcherServlet.java ===
// 每个 HTTP 请求最终都会进入这个方法
// 它是 Spring MVC 的总指挥，协调 HandlerMapping、HandlerAdapter、ViewResolver 等组件

protected void doDispatch(HttpServletRequest request, HttpServletResponse response) throws Exception {

    HttpServletRequest processedRequest = request;
    // HandlerExecutionChain 包含 Handler 和匹配的拦截器列表
    HandlerExecutionChain mappedHandler = null;
    // 标记是否解析过 Multipart（文件上传）
    boolean multipartRequestParsed = false;

    // 获取异步管理器（支持 @Async 和 DeferredResult 等异步请求）
    WebAsyncManager asyncManager = WebAsyncUtils.getAsyncManager(request);

    try {
        ModelAndView mv = null;         // 最终的模型和视图
        Exception dispatchException = null;  // 分发过程中的异常

        try {
            // ===== 第 1 步：文件上传检查 =====
            // 检查请求的 Content-Type 是否是 multipart/form-data
            // 如果是，用 MultipartResolver 解析请求，将文件封装为 MultipartFile
            // 返回包装后的 MultipartHttpServletRequest
            processedRequest = checkMultipart(request);
            multipartRequestParsed = (processedRequest != request);

            // ===== 第 2 步：查找 Handler =====
            // 遍历所有注册的 HandlerMapping（按优先级排序）：
            //   1. RequestMappingHandlerMapping → 匹配 @RequestMapping 注解
            //   2. BeanNameUrlHandlerMapping → 匹配 beanName 以 "/" 开头的 Bean
            //   3. RouterFunctionMapping → 匹配函数式路由
            // 找到第一个匹配的就返回
            //
            // 返回的 HandlerExecutionChain 包含：
            //   handler: HandlerMethod 对象（封装了 Controller 类 + 方法 + 参数信息）
            //   interceptors: 匹配的 HandlerInterceptor 列表
            mappedHandler = getHandler(processedRequest);

            // 如果没有找到匹配的 Handler
            if (mappedHandler == null) {
                // 返回 404 Not Found
                // 抛出 NoHandlerFoundException（如果配置了 throwExceptionIfNoHandlerFound）
                // 或者直接 response.sendError(404)
                noHandlerFound(processedRequest, response);
                return;
            }

            // ===== 第 3 步：查找 HandlerAdapter =====
            // 根据 Handler 的类型找到对应的适配器
            // RequestMappingHandlerAdapter → 处理 HandlerMethod（@RequestMapping 方法）
            // SimpleControllerHandlerAdapter → 处理实现了 Controller 接口的类
            // HttpRequestHandlerAdapter → 处理实现了 HttpRequestHandler 接口的类
            //
            // 为什么需要适配器？因为 Handler 有多种类型，
            // 适配器统一了调用方式（适配器模式）
            HandlerAdapter ha = getHandlerAdapter(mappedHandler.getHandler());

            // ===== 第 4 步：处理 HTTP 缓存（Last-Modified）=====
            // 如果是 GET 或 HEAD 请求，检查资源是否修改过
            // 如果 If-Modified-Since 头匹配，直接返回 304 Not Modified
            String method = request.getMethod();
            boolean isGet = HttpMethod.GET.matches(method);
            if (isGet || HttpMethod.HEAD.matches(method)) {
                long lastModified = ha.getLastModified(request, mappedHandler.getHandler());
                if (new ServletWebRequest(request, response).checkNotModified(lastModified) && isGet) {
                    return;  // 304，不需要执行 Handler
                }
            }

            // ===== 第 5 步：执行拦截器 preHandle =====
            // 按注册顺序依次调用每个拦截器的 preHandle() 方法
            // 如果任何一个拦截器返回 false：
            //   1. 调用已执行的拦截器的 afterCompletion()（逆序）
            //   2. 直接 return，不执行 Handler
            // 典型用途：登录检查、权限校验、请求日志
            if (!mappedHandler.applyPreHandle(processedRequest, response)) {
                return;  // 被拦截器拦截了，直接返回
            }

            // ===== 第 6 步：执行 Handler（Controller 方法）=====
            // 这是请求处理的核心！
            // RequestMappingHandlerAdapter.handle() 内部流程：
            //   1. 创建 ServletInvocableHandlerMethod
            //   2. 设置参数解析器（处理 @RequestParam、@PathVariable、@RequestBody 等）
            //   3. 设置返回值处理器（处理 @ResponseBody、ModelAndView、String 等）
            //   4. 解析方法参数（每个参数找对应的 ArgumentResolver 解析）
            //   5. 反射调用 Controller 方法（method.invoke(bean, args)）
            //   6. 处理返回值（如果是 @ResponseBody，直接写入响应体）
            //   7. 返回 ModelAndView（如果是 @ResponseBody，mv=null）
            mv = ha.handle(processedRequest, response, mappedHandler.getHandler());

            // 异步请求判断
            // 如果 Controller 返回了 DeferredResult、Callable、WebAsyncTask
            // 则异步处理已经启动，当前线程直接返回
            if (asyncManager.isConcurrentHandlingStarted()) {
                return;
            }

            // 如果 Handler 没有返回视图名，使用默认的
            // 默认视图名根据请求 URL 生成（如 /user/list → "user/list"）
            applyDefaultViewName(processedRequest, mv);

            // ===== 第 7 步：执行拦截器 postHandle =====
            // 按注册的逆序执行（先注册的后执行）
            // 此时 Handler 已经执行完毕，mv 已经生成
            // 拦截器可以修改 ModelAndView
            mappedHandler.applyPostHandle(processedRequest, response, mv);
        }
        catch (Exception ex) {
            // 记录异常，稍后处理
            dispatchException = ex;
        }
        catch (Throwable err) {
            dispatchException = new ServletException("Handler dispatch failed", err);
        }

        // ===== 第 8 步：处理分发结果 =====
        // processDispatchResult() 内部：
        //   1. 如果有异常 → 调用 HandlerExceptionResolver 处理
        //      ExceptionHandlerExceptionResolver 会查找：
        //        a. Controller 类中的 @ExceptionHandler 方法
        //        b. @ControllerAdvice 类中的 @ExceptionHandler 方法
        //   2. 如果有 ModelAndView → ViewResolver 解析视图 → View.render() 渲染
        //      对于 @ResponseBody，mv=null，不需要视图渲染
        //   3. 调用拦截器的 afterCompletion()（逆序，无论是否异常都执行）
        processDispatchResult(processedRequest, response, mappedHandler, mv, dispatchException);
    }
    catch (Exception ex) {
        // 触发拦截器的 afterCompletion（异常情况）
        triggerAfterCompletion(processedRequest, response, mappedHandler, ex);
    }
    finally {
        // 异步请求的后续处理
        if (asyncManager.isConcurrentHandlingStarted()) {
            if (mappedHandler != null) {
                mappedHandler.applyAfterConcurrentHandlingStarted(processedRequest, response);
            }
        } else {
            // 清理 Multipart 资源（删除临时上传文件）
            if (multipartRequestParsed) {
                cleanupMultipart(processedRequest);
            }
        }
    }
}
```

### @RequestBody 参数解析

> 文件：`RequestResponseBodyMethodProcessor.java`

```java
// === RequestResponseBodyMethodProcessor.java ===
// 处理 @RequestBody 注解的参数解析器
// 同时也是 @ResponseBody 的返回值处理器（双重身份）

// 参数解析
@Override
public Object resolveArgument(
        MethodParameter parameter,          // 方法参数（包含注解、类型信息）
        ModelAndViewContainer mavContainer,  // 模型和视图容器
        NativeWebRequest webRequest,         // 原始请求
        WebDataBinderFactory binderFactory)  // 数据绑定工厂
        throws Exception {

    // 获取方法参数的信息（可能是嵌套的泛型类型）
    parameter = parameter.nestedIfOptional();

    // 使用 HttpMessageConverter 从请求体读取数据
    // 选择 Converter 的逻辑：
    //   1. 获取请求的 Content-Type（如 application/json）
    //   2. 遍历所有注册的 HttpMessageConverter
    //   3. 找到第一个同时满足以下条件的 Converter：
    //      a. canRead(parameterType, contentType) == true
    //      b. 支持目标 Java 类型
    //   4. 调用 converter.read(parameterType, inputMessage) 读取并反序列化
    //
    // 对于 JSON：使用 MappingJackson2HttpMessageConverter
    //   → ObjectMapper.readValue(inputStream, User.class)
    //   → 将 JSON 字符串反序列化为 Java 对象
    Object arg = readWithMessageConverters(webRequest, parameter, parameter.getNestedGenericParameterType());

    // 获取参数名称（用于错误消息）
    String name = Conventions.getVariableNameForParameter(parameter);

    // 数据校验（@Valid 或 @Validated）
    if (binderFactory != null) {
        WebDataBinder binder = binderFactory.createBinder(webRequest, arg, name);
        if (arg != null) {
            // 如果参数上有 @Valid 或 @Validated 注解
            // 执行 JSR-303 Bean Validation
            // 校验失败会收集到 BindingResult 中
            validateIfApplicable(binder, parameter);

            // 如果有校验错误且方法参数后面没有紧跟 BindingResult 参数
            // 直接抛出 MethodArgumentNotValidException
            // 这就是你在 @ControllerAdvice 中经常处理的异常
            if (binder.getBindingResult().hasErrors() && isBindExceptionRequired(binder, parameter)) {
                throw new MethodArgumentNotValidException(parameter, binder.getBindingResult());
            }
        }
    }

    // 如果参数类型是 Optional，包装一层
    return adaptArgumentIfNecessary(arg, parameter);
}
```

### @ResponseBody 返回值处理

```java
// === RequestResponseBodyMethodProcessor.java ===
// 处理 @ResponseBody 的返回值

@Override
public void handleReturnValue(
        Object returnValue,                  // Controller 方法的返回值
        MethodParameter returnType,          // 返回类型信息
        ModelAndViewContainer mavContainer,  // 模型和视图容器
        NativeWebRequest webRequest)         // 原始请求
        throws IOException, HttpMediaTypeNotAcceptableException, HttpMessageNotWritableException {

    // 标记请求已经直接处理了，不需要视图渲染
    // DispatcherServlet 看到这个标记后，不会走 ViewResolver
    mavContainer.setRequestHandled(true);

    // 创建输入/输出消息对象
    ServletServerHttpRequest inputMessage = createInputMessage(webRequest);
    ServletServerHttpResponse outputMessage = createOutputMessage(webRequest);

    // 使用 HttpMessageConverter 将返回值写入响应体
    // 选择 Converter 的逻辑：
    //   1. 确定响应的 Content-Type（内容协商）：
    //      a. 检查 @RequestMapping(produces = "application/json")
    //      b. 检查请求的 Accept 头（如 Accept: application/json）
    //      c. 如果都没指定，使用默认的（application/json 或 application/xml）
    //   2. 遍历所有 HttpMessageConverter
    //   3. 找到能写入目标类型 + 目标 MediaType 的 Converter
    //   4. 调用 converter.write(returnValue, mediaType, outputMessage)
    //
    // 对于 JSON：MappingJackson2HttpMessageConverter
    //   → ObjectMapper.writeValue(outputStream, returnValue)
    //   → 将 Java 对象序列化为 JSON 字符串
    //   → 设置 Content-Type: application/json
    //   → 写入 HttpServletResponse 的 OutputStream
    //
    // 写入前后会调用 RequestBodyAdvice / ResponseBodyAdvice（如果有）
    //   ResponseBodyAdvice 典型用途：统一包装返回结构 { code: 200, data: {...} }
    writeWithMessageConverters(returnValue, returnType, inputMessage, outputMessage);
}
```
