# IDEA 调试手册

这份手册用于解决读 Spring 源码时最常见的调试问题。

## 推荐设置

```text
Project SDK: JDK 17
Gradle JVM: JDK 17
Run tests using: Gradle
```

## 常用调试按钮

| 操作 | 作用 | 什么时候用 |
|------|------|------------|
| Step Over | 执行当前行，不进入方法 | 主线清楚，只想往下走 |
| Step Into | 进入当前方法 | 当前方法是关键入口 |
| Force Step Into | 强制进入框架/库方法 | IDEA 默认不进入时使用 |
| Step Out | 跳出当前方法 | 进入太深，需要回到上一层 |
| Resume | 继续到下一个断点 | 断点太密时使用 |
| Drop Frame | 回退一层调用栈 | 想重新观察某一段逻辑 |

## 条件断点

Spring 源码中很多方法会被调用很多次。新手最常遇到的是断点命中太多。

例如在 `AbstractBeanFactory.doGetBean(...)` 上设置条件：

```java
"myService".equals(beanName)
```

如果不知道 Bean 名称，先不加条件，第一次命中后看 Variables 面板中的 `beanName`。

## 日志断点

如果不想每次暂停，可以用日志断点。

建议输出：

```text
beanName = {beanName}
```

适合观察：

- 哪些 Bean 被创建
- 哪些 Bean 被代理
- 哪些依赖被解析

## 看 Variables 面板

读 Spring 源码时优先看这些变量：

| 变量 | 说明 |
|------|------|
| `beanName` | 当前正在处理的 Bean 名称 |
| `mbd` | 合并后的 BeanDefinition |
| `beanFactory` | 当前容器 |
| `bdName` | BeanDefinition 名称 |
| `bean` | 当前 Bean 实例 |
| `exposedObject` | 最终暴露给容器的对象，可能是代理 |
| `descriptor` | 依赖描述，例如字段、参数、是否 required |

## 看 Call Stack

Call Stack 比单步更重要。它告诉你当前代码是怎么走到这里的。

建议关注：

```text
refresh()
  -> finishBeanFactoryInitialization()
  -> preInstantiateSingletons()
  -> getBean()
  -> doGetBean()
  -> doCreateBean()
```

## 断点命中太多怎么办

1. 加条件断点。
2. 换更靠近业务的测试类。
3. 只调试单个测试方法。
4. 使用日志断点代替普通断点。
5. 跳过工具方法，回到主链路。

## 第一次推荐断点

| 断点 | 目的 |
|------|------|
| `AbstractApplicationContext.refresh()` | 进入容器启动主流程 |
| `ConfigurationClassPostProcessor.processConfigBeanDefinitions(...)` | 观察配置类解析 |
| `DefaultListableBeanFactory.preInstantiateSingletons()` | 观察单例预实例化 |
| `AbstractBeanFactory.doGetBean(...)` | 观察 Bean 获取 |
| `AbstractAutowireCapableBeanFactory.doCreateBean(...)` | 观察 Bean 创建 |
| `AutowiredAnnotationBeanPostProcessor.postProcessProperties(...)` | 观察 `@Autowired` 注入 |
