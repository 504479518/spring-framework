# 学习成果检查清单

用这份清单判断自己是否真的读懂，而不是只看过。

## 第一周：IoC 容器

- [ ] 能画出 `refresh()` 主流程。
- [ ] 能说明 `BeanDefinition` 和 Bean 实例的区别。
- [ ] 能解释 `ConfigurationClassPostProcessor` 的作用。
- [ ] 能从 `preInstantiateSingletons()` 跟到 `doGetBean()`。
- [ ] 能从 `doGetBean()` 跟到 `doCreateBean()`。
- [ ] 能说明 Bean 创建的三阶段：实例化、属性填充、初始化。
- [ ] 能解释 `@Autowired` 字段注入的入口。
- [ ] 能说明 `BeanFactoryPostProcessor` 和 `BeanPostProcessor` 的差异。

## 第二周：AOP 与事务

- [ ] 能说明 AOP 为什么通过 `BeanPostProcessor` 接入。
- [ ] 能解释一个 Bean 什么时候变成代理对象。
- [ ] 能区分 JDK 动态代理和 CGLIB。
- [ ] 能画出 `ReflectiveMethodInvocation.proceed()` 拦截器链。
- [ ] 能说明 `@Transactional` 如何变成 Advisor。
- [ ] 能从 `TransactionInterceptor.invoke()` 跟到 commit/rollback。
- [ ] 能解释 `REQUIRED` 和 `REQUIRES_NEW` 的差异。
- [ ] 能说明事务信息为什么绑定在线程上。

## 第三周：MVC 与 WebFlux

- [ ] 能画出 `DispatcherServlet.doDispatch()` 流程。
- [ ] 能说明 HandlerMapping 和 HandlerAdapter 的区别。
- [ ] 能解释参数解析器如何选择。
- [ ] 能解释返回值处理器如何选择。
- [ ] 能说明 `@ExceptionHandler` 如何被找到。
- [ ] 能说明 MVC 和 WebFlux 的核心差异。
- [ ] 能画出 `DispatcherHandler.handle()` 的响应式链路。
- [ ] 能解释什么时候适合用 WebFlux。

## 自测题

1. `refresh()` 中哪一步会触发 `@Configuration` 解析？
2. `BeanDefinition` 什么时候被注册，Bean 实例什么时候被创建？
3. 为什么 `@Autowired` 是 `BeanPostProcessor` 处理的？
4. AOP 代理为什么可能导致 `this` 调用失效？
5. `@Transactional` 默认遇到受检异常会回滚吗？为什么？
6. MVC 中请求是如何从 URL 映射到 Controller 方法的？
7. WebFlux 为什么不建议在 EventLoop 里调用阻塞 API？
